## Intent

Tokenizer 让使用者围绕一个稳定的 combobox input，把一组可搜索的值构建并编辑为可移除的 token。它拥有字段表面、token/input 布局、建议菜单关系，以及从任务起始处的控件打开相关表面所需的包内身份标识。

本记录保留已发布的 Tokenizer 事实，并定义三项由组件拥有的契约：一个供 Core 同级模块使用的包内打开控件描述符、空查询 bootstrap 菜单的选择后生命周期，以及一种触摸呈现——在紧凑粗指针屏幕上为默认值——其中触发元素会打开一个可搜索的模态 bottom sheet，以取代 inline combobox。该描述符让 Layer 能够准备放置位置，而不会向使用方暴露 DOM refs、指针坐标或宽度策略。`component:PowerSearch` 消费该描述符；它不是本记录的权威。

## Compatibility and migration

- 稳定的公共 API 与默认的 `hasEntriesOnFocus={false}` 路径保持不变。
- 兼容性类别：针对现有 opt-in 的 `hasEntriesOnFocus` 模式的有意行为修正。来自其当前空查询 bootstrap 队列的一次已提交选择，会让其余符合条件的已加载选项保持可用，而不是在每次选择后关闭菜单。
- 受控/非受控归属不变。保留行为跟随已提交的受控值；调用方尚未接受的提议值仍然可用。
- 稳定呈现（DEC-3）：`presentation` 是稳定 prop，从实验性选项（`spec:AST-017/FR23`）提升而来。该 API 变更是增量的：该 prop 是新增且可选的，且没有移除或收窄任何现有稳定 prop、类型或导出。实验性写法（`experimental` prop 内的 `presentation`）被移除且未保留为别名：它不在稳定兼容性承诺范围内，因此其移除是一次 `[experimental]` patch 变更，其说明会指出替代写法（`spec:AST-017/FR22`）。对于使用该写法的调用方，`astryx upgrade` 会改写静态用法，并在无法证明可改写之处留下 TODO，例如在展开 props 的 Tokenizer 上（`spec:AST-017/FR23`）。
- 默认值变更（DEC-3）：`presentation` 默认改为 `adaptive`，这是对已发布的 `popover` 默认值的变更，行为只在紧凑粗指针屏幕上改变，而这正是 `adaptive` 的用途。在精细指针下、屏幕不紧凑时、服务端以及水合过程中，未设置 `presentation` 的字段会与之前完全一样地渲染 inline combobox（`spec:AST-017/FR59`）。在紧凑粗指针屏幕上它会渲染 sheet：`onChange` 在 Save 时触发一次，而不是每次选择触发一次；`ref` 接收触发按钮；除 `endContent` 与 `renderToken` 之外，inline combobox 的 props 都不会渲染。`presentation="popover"` 在所有设备上保持先前行为。该稳定 prop 与此默认值在同一个 patch 中以 `[feat]` 发布：该发布层级是工程负责人的产品决策，并已获得 `spec:AST-017` 负责人的同意（DEC-3）。
- 迁移决策：`presentation="popover"` 会在所有设备上恢复先前的呈现面、input、`onChange` 时机与 `ref` 元素——这正是恢复用 input `spec:AST-017/DEC-23` 与 `architecture:public-component-api/INV16` 所指的内容。没有 codemod 会添加它，因为给每个 Tokenizer 都加上它会让所有调用方退出新默认值。省略 `hasEntriesOnFocus`、类型化搜索选择、显式关闭、disabled 状态、最大条目状态与源加载行为的现有调用方，保留其原有边界。
- 被拒绝的关闭（FR27，`component:BottomSheet` DEC-5）：当丢弃确认框打开时，sheet 会停在其 peek 处等待，而不是在对话框下方弹回其停靠位。对话框、其措辞、焦点与结果、草稿、Save、`value` 与 `onChange` 均不变，也没有任何 prop 变化。这是一次 `[feat]` patch 变更（`spec:AST-017/FR7`、`/FR25`）。

使用方的迁移说明属于使用方文档与发布说明。

## Ownership boundary

**拥有**

- 持有 token 集合、稳定的原生 search input，以及包含它们的绘制外层字段/控件表面。
- Tokenizer 自身焦点 bootstrap 建议菜单在一次已提交选择之后的生命周期，包括排除已选值、选择下一个选项、焦点连续性与终态关闭状态。
- 在 Tokenizer 内发起的任务所用的活动打开控件：添加/搜索工作用内部 input，编辑工作用实际被激活的 token/控件。
- 这些元素在一个包内描述符中的身份标识、可用性、生命周期与安全回退语义。
- Tokenizer 当前的 suggestion-menu 宽度与最小锚点宽度行为。
- Token 换行，以及 `none`、`unfocusedInline` 与 `unfocusedLayer` 溢出呈现。
- 触摸 sheet 呈现：其触发元素、单个可搜索 sheet、会话内的行顺序、渐进式长列表渲染、创建行、需确认的 Clear all、带 Save 的草稿与在丢弃已变更草稿前询问的守卫（FR26、FR27、DEC-4），以及 sheet 遵循哪些 Tokenizer props。

**不拥有 / 非目标**

- 通用的 BaseTypeahead 选择策略。直接单选 BaseTypeahead 与 Typeahead 保留其 select-clear-close-refocus 生命周期。
- 针对类型化查询选择的新规则，或要求在每次 Tokenizer 选择后重新获取建议。
- 通用锚点定位、top-layer 承载、视口碰撞、生成的锚点名称或 prepared-placement 生命周期——由 `architecture:layer-runtime` 拥有。
- PowerSearch 编辑器尺寸，包括其提议的 400–720 CSS px 范围——若该草案获批，由 `component:PowerSearch` 拥有。
- 公共 input ref、打开控件 ref、锚点描述符、最大菜单宽度、坐标、放置或指针跟踪 API。
- 对已发布 `menuWidth` 语义的变更。它仍是精确的偏好像素宽度，其渲染出的菜单不会收缩到 Tokenizer 外层字段以下。
- 使用方提供的 token 内容与视觉。Tokenizer 只拥有识别激活内部打开操作的控件所需的捕获边界。
- `adaptive` 背后的紧凑触摸判定规则，由 `spec:AST-094/FR13` 拥有（触摸呈现在水合之后、粗主指针下适用；紧凑为 `spec:AST-012/FR9`）。Tokenizer 与选择控件一样，用这一条规则判定 `adaptive`；它不增加自己的查询。
- sheet 的对话框、遮罩、手势、吸附行为与关闭路径——由 `component:BottomSheet` 与 `family:overlay-dismissal` 拥有；其屏幕键盘行为——由 `spec:AST-099` 拥有。本记录拥有的是：结果上的哪一次触摸会把焦点移出 sheet 的搜索字段以及移到何处（FR18），而不是键盘在此时做什么；以及 sheet 在其草稿被变更时如何处理关闭（FR27），而不是手势或其路径。

## Public concepts

引入一个稳定的公共概念：`presentation` prop，取值为 `'popover' | 'bottom-sheet' | 'adaptive'`，默认 `adaptive`，类型由导出的 `TokenizerPresentation` 定义，即选择控件的取值集（DEC-3）。现有的使用方 props 与用法仍保留在 `Tokenizer.doc.mjs` 中。现有的 `hasEntriesOnFocus` 模式包含 FR13–FR15 中由组件拥有的选择后行为。

在 sheet 呈现中，字段的控件盒承载触发按钮、tokens 与 `endContent`，并带有 `tokenizer` 主题目标和它的 `data-*` 状态属性以及焦点环（`:focus-within`），与 inline 字段的盒相同。触发元素就是控件：`ref`、`id`、调用方的 `data-*` 与 `aria-*` 以及其他基础 props 都到达它（`family:input-fields/FR10`、`architecture:public-component-api/INV8`），`handleRef.focus()` 与 `blur()` 作用于它，`onKeyDown` 报告它的事件。`onFocus` 与 `onBlur` 报告焦点进入与离开字段的盒，该盒还承载 `endContent` 与自定义 token 的控件，正如 inline 字段报告其 wrapper。导出的 `TokenizerProps` 仍是 interface，并保留发布时的 `ref?: Ref<HTMLInputElement>`，因此 `interface X extends TokenizerProps<T>` 与 `Omit<TokenizerProps<T>, …>` 包装器仍可编译；组件自身的参数类型还接受 `Ref<HTMLInputElement | HTMLButtonElement>`。ref 在 sheet 呈现中接收触发按钮，在其他情况下接收 combobox input，因此为两种元素标注的 ref 能描述它所承载的内容。在 sheet 呈现中，`endContent` 渲染在字段的行内末端，`renderToken` 渲染字段的 tokens，与 inline 字段一致。只描述 inline combobox 的 props 在 sheet 呈现中没有表面：`renderItem`、`hasClear`（由 sheet 自己的 Clear all 取代）、`hasEntriesOnFocus`（sheet 始终列出 bootstrap 集合）、`menuWidth`、`menu` 与 `onOpenChange`（sheet 保留自己的表面）、`tokenOverflowBehavior`（字段会换行其 tokens）与 `hasAutoFocus`。在 sheet 呈现下传入其中任何一个会发出一次开发模式警告，指出该 prop 与 `presentation="popover"`，因此它不会被静默丢弃（`architecture:public-component-api/INV3`）；其他所有 prop 保持其含义。

该描述符是包内的。它必须不出现在导出的 `TokenizerProps`、公共 barrel、生成的声明、使用方文档、CLI 输出与 Changesets 中。当前的 `handleRef` 仍是公共的 focus/blur handle，它也会打开与关闭 inline 菜单（`open()`、`close()`；FR28）；它不会变成元素或几何的逃生通道。

### Allowed variation

- **AV1 — Token 呈现。** 默认 Token 控件与自定义 `renderToken` 内容在视觉上可以不同。当可识别的后代控件发起激活时，打开控件的捕获边界仍归 Tokenizer 所有。
- **AV2 — 溢出呈现。** token 可以正常换行、在未聚焦时截断，或随活动输入移动到 `unfocusedLayer`。这些模式可以改变元素几何，但不得改变描述符身份或回退顺序。
- **AV3 — 内部表示。** 描述符可以使用 ref、元素、回调注册，或等效的 Core 私有表示。它必须保持 FR4–FR8，并且不得进入公开声明。
- **AV4 — 层机制。** Layer 可以通过零尺寸标记、分开的尺寸锚点与位置锚点，或满足 FR9–FR12 与当前 Layer 架构的另一内部机制，实现被锁存的边缘。
- **AV5 — 响应式移动。** 打开期间，CSS 可以跟随外层字段的移动、容器尺寸变化、书写方向与碰撞。JavaScript 在下次打开之前不会重新测量或选择新的首选边缘。
- **AV6 — 内部保留机制。** Tokenizer 与 BaseTypeahead 可以通过包私有机制保留、投射或以其他方式协调已稳定的队列。该机制必须保持 FR13–FR15，不得成为公开 API，也不得改变直接单选的 BaseTypeahead 行为。
- **AV7 — 面板表面构成。** 底部面板呈现可以用任意内部结构组合 BottomSheet、共享的面板搜索字段、EmptyState、确认对话框与 checkbox 指示器，并按需加载该表面，前提是 FR16–FR24、FR26、FR27、AR6 与 PR6 成立，且结构保持在 `architecture:component-style-authoring` INV7 — 最小 DOM、内容只渲染一次；静止时，针对指针方式的呈现是在相同元素上改变属性与样式；打开时，用 INV7 的话说，“粗指针下的打开层元素数量至多与细指针下相同（超出部分，仅限打开层余量 `spec:AST-017` FR60 与 DEC-29 所设定的）”。关闭的 `adaptive` 面板字段（不同的元素，任何余量都不涵盖）与打开的面板（超过 FR60 允许的五个额外元素）是所有者例外，由 DEC-3 记录，超出该余量，并附有它们的前后计数。

### Transformation and precedence order

- **ORD1 — 表面宽度。** 解析使用方组件的首选表面宽度。Tokenizer 不贡献任何 PowerSearch 宽度值。
- **ORD2 — 全宽判定。** 如果首选表面宽度大于或等于外层字段宽度，则使用外层字段与逻辑起始。不要读取或应用打开控件的几何来决定边。
- **ORD3 — 打开控件。** 对于更窄的表面，在可用时使用实际捕获的 token/控件；否则使用稳定的内部输入框；再否则使用逻辑起始处的外层字段。
- **ORD4 — 边的选择。** 将可用控件与外层字段的物理起始和结束相比较，选择较近的边，并将其映射为逻辑起始/结束。平局解析为逻辑起始。
- **ORD5 — 隐藏时提交。** 在隐藏时提交宽度模式、锚点与对齐；在下一个动画帧显示，并锁定结果直到关闭。
- **ORD6 — 碰撞。** 最后应用 Layer 由 CSS 拥有的视口与安全区碰撞行为。碰撞不会重新开启语义边判定。

### Performance and resources

- **PR1 — 渲染期不做测量。** Tokenizer 与描述符使用方都不得在 React 渲染期间读取几何。
- **PR2 — 每次打开一个读取批次。** 打开准备在一个批次读取阶段中读取外层字段，并且仅在需要时读取打开控件。带插桩的验证必须对同一次打开的第二个准备批次判为失败。
- **PR3 — 隐藏时准备。** 锚点、宽度模式与对齐在表面隐藏时提交；显示发生在下一个动画帧。在该帧之前关闭或卸载会取消挂起的显示。
- **PR4 — 不做持续跟踪。** 本契约不新增指针跟踪、常开的 ResizeObserver、全局 resize 监听器或重复的几何读取。
- **PR5 — 持续几何由 CSS 拥有。** 在这一次性的语义选择之后，容器尺寸变化、外层字段移动、书写方向布局与最终碰撞仍属于 CSS/Layer 的工作。
- **PR6 — sheet 表面只在其呈现处产生开销。** 解析为 `popover` 的字段——默认情况下，每个具有精细指针或在非紧凑屏幕上的字段——不会加载 sheet 表面的代码；只有当字段解析为 `bottom-sheet` 时才按需加载该表面，它在服务器上或水合渲染期间不渲染任何内容，并分批渲染其长列表（FR21）。

## Accessibility contract

AR1–AR5 与 AR7 描述 `popover` 呈现；AR6 描述 sheet 呈现。

- **AR1 — 模态等价性。** 同一个输入框或 token/控件在指针、触摸、键盘与程序化激活下产生相同的首选放置。不参与任何指针坐标。
- **AR2 — 语义稳定性。** 描述符与放置工作不得改变 Tokenizer 的字段、分组、combobox、listbox、option、token、播报、禁用、焦点或关闭语义。
- **AR3 — 焦点稳定性。** 既有的聚焦/重新聚焦行为在添加、移除、清空、溢出展开/折叠，以及相关表面的打开/关闭之后仍然保持。例外：当字段的输入框未获焦点时，用手指点按 Token 渲染的移除按钮会移除该 token，并把焦点留在原处，因此屏幕键盘保持收起；如果该移除按钮或它所在 token 中的另一个控件持有焦点，则焦点移到输入框；用笔、鼠标或键盘进行的移除，以及自定义 `renderToken` 绘制的移除控件，都保持上述焦点行为。
- **AR4 — 没有可见的放置错误。** 使用者不得看到表面首先绘制在外层起始或过期位置，随后跳到其解析出的边。无效标识在显示之前回退，而不是闪烁或显示错误。
- **AR5 — 保留的 combobox 语义。** 当焦点引导的菜单在选择之后仍保持打开时，DOM 焦点必须留在 combobox 上，`aria-expanded` 必须保持为 true，且 `aria-activedescendant` 必须指向已渲染的下一个有效选项。因关闭、禁用、达到上限或耗尽而关闭时，必须移除活动后代。已选中与已禁用的选项永远不可交互。
- **AR6 — Sheet 语义。** 在 sheet 呈现中，触发器是一个由字段标签命名的按钮，带有 `aria-haspopup="dialog"` 与 `aria-expanded`，其可访问描述就是内联输入框的全部描述，顺序与内联输入框一致——调用方的 `aria-describedby` id、字段 `description`、状态消息，以及禁用时的 `disabledMessage` 原因（禁用控件在自身上暴露其描述与原因，`spec:AST-085/FR5`）——随后是已选数量与已选 token 标签，因此明眼人所看到的选择会作为触发器的描述暴露给辅助技术；这些标签就是已渲染的 token 本身，每个都在一个隐藏计数之后通过 id 从 `aria-describedby` 引用，因此没有标签渲染两次（`architecture:component-style-authoring` INV7）；来自 `renderToken` 的自定义 token 可以持有控件，其名称会加入描述，而调用方的标记无法脱离这些控件被引用，因此每个自定义 token 改为由一份其条目标签的副本来描述，该副本带有 `hidden` 属性，`aria-describedby` 会读取它而无障碍树会将其排除，因此每个标签在无障碍树中出现一次（下方的 INV7 例外记录这些副本）；屏幕阅读器是否随按钮朗读描述取决于该屏幕阅读器（`spec:AST-009/FR8`），而 DOM 与无障碍树证明 `aria-describedby` 的暴露（WCAG 2.2 SC 1.3.1 与 4.1.2，经由 `spec:AST-020/FR1`）；sheet 是一个由字段标签命名的模态对话框；搜索字段命名为 `Search {label}`，并带有一个具名的清除操作；每一行都是一个由其条目标签命名的 `checkbox`，带有 `aria-checked`，可通过点按或点击以及 Space 与 Enter 切换，即其渲染所基于的原生按钮的激活键（`spec:AST-020/FR15`；WCAG 2.2 SC 2.1.1 与 4.1.2）；禁用的行与禁用的触发器使用 `aria-disabled` 并保持其焦点顺序；在 sheet 打开期间，添加、移除、经确认的 Clear all（“All items removed”，在确认关闭之后发出，因为确认覆盖 sheet 时发出的消息不会被听到——`spec:AST-086/FR14`）、搜索的忙碌开始，以及每次搜索如何结束——非空查询的结果数量，或空状态显示时其文本，二者都来自搜索自身的 `useAnnounce({hasReplace: true})` 实例（`spec:AST-086/FR9`、FR13），因此较新的一个会替换尚未朗读的那个——都会在 sheet 内部通过 `useAnnounce` 每次时机播报一次，`spec:AST-086/FR14` 在其打开期间把它路由进 sheet 自身对话框的持久礼貌容器，因为共享的页面正文通道在原生模态之后不会暴露；该容器遵循该记录的 FR3、FR5 与 FR6（WCAG 2.2 SC 4.1.3，经由 `spec:AST-020/FR1`）。sheet 关闭后，焦点回到触发器，字段的播报从字段渲染的任何位置遵循同一条 FR14 路由。
- **AR7 — Clear all 会被播报。** 在 `popover` 呈现中，字段的 Clear all 会一次性清空每个 token 并把焦点移到输入框，它播报“All items removed”（`@astryx.tokenizer.allRemoved`，即 AR6 中 sheet 的 Clear all 所用措辞），方式与字段播报 token 添加或移除相同：礼貌地，经由共享通道（`spec:AST-086/FR2`、FR5）。每次 Clear all 播报一次（`spec:AST-086/FR6`）；在 sheet 中确认的 Clear all 只由 sheet 播报（AR6），字段对它保持沉默（WCAG 2.2 SC 4.1.3，经由 `spec:AST-020/FR9`）。组合 Tokenizer 并自行措辞其 Clear all 的组件改为播报自己的措辞（`component:PowerSearch`）。在 `popover` 呈现中，组合 Tokenizer 并锁定部分 token 的组件会保留它们：Clear all 只移除其他 token，且仅当存在一个时才显示，而当最后一个 token 被锁定时，Backspace 不移除任何内容（`component:PowerSearch` FR23）。

## Family and system relationships

- `family:overlay-dismissal` 继续为 Tokenizer 的 BaseTypeahead/Layer 表面拥有共享的 Escape 与平台关闭顺序。
- `architecture:layer-runtime` 拥有生成的锚点名称、锚点组合、已准备的放置、顶层托管、视口碰撞、可见性协调与清理。Tokenizer 提供标识，而非 Layer 机制。
- `architecture:interaction-modality` 拥有共享的模态状态。打开放置有意不基于该状态分支。
- `architecture:public-component-api` 与 `spec:AST-002/DEC-1` 让可推导的几何与包对等标识不进入 Tokenizer 的公开 API。
- 当前的 Typeahead 草案记录了 BaseTypeahead 的层委托，但不拥有 Tokenizer 的 token/输入标识或已批准描述符。
- `family:input-fields` 拥有家族级的状态显示、行为、外观、尺寸、结束控件、禁用原因与状态放置策略。Tokenizer 在该边界之内保持其组件本地的 token/输入与源加载行为。
- `component:PowerSearch` 依赖已批准描述符并拥有自己的编辑器宽度策略；它不是 Tokenizer 的权威。

### Required implementation and browser evidence

选择后的生命周期必须同时更新所属源码、聚焦测试、使用方文档与 Changeset。精确 head 的浏览器证据必须检验：

1. 从已定型的焦点引导候选项集出发进行指针与键盘选择，已提交的值被移除，弹出层仍然打开，输入焦点保持不变，下一个剩余选项处于活动状态。
2. 已提交选项是最后一个时的回退，以及没有剩余选择与 `maxEntries` 时的终止关闭。
3. Escape、Tab 或焦点向外离开，向禁用状态过渡，以及挂起或过期源定型后不再重新打开。
4. `hasEntriesOnFocus` 关闭时的未变路径，以及直接单选 BaseTypeahead 选择仍然关闭的情况。

单独的打开控件描述符仍处于待定状态。当该描述符及其 Layer 使用方交付时，它们必须补充可截图的证据：全宽/等宽/窄宽、换行 token、溢出层、LTR/RTL、碰撞、过期回退与首次绘制。带插桩的验证必须证明每次打开只有一个几何读取批次。PowerSearch 的单独证据拥有其编辑器尺寸；这些尺寸永远不会成为 Tokenizer 的策略。

## Decision log

### DEC-1 — Opening control is package-internal and read once per open

**Reference:** `component:Tokenizer/DEC-1`

**Decider:** `cixzhang`, `2026-08-31`

Tokenizer 为 Core 同类组件提供一个包内描述符，用于表示稳定的外框字段身份与活动打开控件身份。使用该描述符的界面先解析自身的首选宽度：与字段至少同样宽的界面按逻辑起始边对齐到外框字段；只有更窄的界面才可以从可用的打开控件选择更近的外侧物理边缘，并以逻辑起始边作为平局时的选择与安全回退。该选择与交互模态无关，并在一次打开的生命周期内保持不变。

打开前的准备工作一次性读取外框字段，并仅在需要时读取打开控件，在隐藏状态下确定宽度模式、锚点与对齐方式，在下一个动画帧显示，且不进行持续跟踪。Tokenizer 的公共 API 保持不变。实现必须提供真实 Chromium 环境下的打开状态证据，覆盖全宽与更窄的放置、LTR 与 RTL、受约束的碰撞、过期回退，以及首次绘制时不出现可见跳动。

### DEC-2 — Focus bootstrap supports consecutive committed selections

**Reference:** `component:Tokenizer/DEC-2`

**Decider:** `cixzhang`, `2026-09-19`

当启用 `hasEntriesOnFocus` 时，从当前已稳定的空查询引导候选项中提交一个选择后，弹层会保持打开，并保留其余符合条件的已加载选择。已提交的值按 `SearchableItem.id` 排除；标签相同的不同条目仍然符合条件。已提交选择之后的下一个选项按显示顺序成为活动项；若其后没有选项，则最近的前一个选项成为活动项。输入焦点与有效的 combobox/listbox ARIA 关系保持完好。

在不再有符合条件的已加载选择、达到 `maxEntries`、控件被禁用、焦点离开，或用户主动关闭时，弹层关闭并清除其活动后代。待处理或过期的数据源工作无法重新打开已终止的弹层，也无法让过期选择变为可交互。本决策不新增公共 API，不要求重新获取数据，也不改变键入查询时的选择行为或直接单选 BaseTypeahead 的行为。

### DEC-3 — The touch sheet is a stable presentation, and adaptive is the default

**Reference:** `component:Tokenizer/DEC-3`

**Decider:** `imdreamrunner`, `2026-11-03`

Tokenizer 通过稳定的 `presentation` 属性提供其触摸界面，取值与各选择控件所用的 `popover`、`bottom-sheet` 和 `adaptive` 一致，默认值为 `adaptive`：在紧凑的粗指针屏幕上使用底部面板（此时内联 combobox 会与软键盘相互争夺），在其他所有场景使用内联 combobox。调用方显式指定的取值在任何设备上都优先；`popover` 保留内联 combobox、其按选择触发的 `onChange` 以及其输入框的 `ref`（`architecture:public-component-api` INV16）。`adaptive` 通过共享的紧凑粗指针策略解析，因此同一页面上的 Tokenizer 与 Selector 会一起切换。取值集合就是各选择控件的 `AdaptivePresentation`，因为 Tokenizer 与 MultiSelector 一样，从可搜索列表中挑选多个条目。稳定的属性与 `adaptive` 默认值在同一次补丁版本中一起发布：API 变更是增量的，行为仅在紧凑粗指针屏幕上改变，而 `presentation="popover"` 在所有场景都保留原有行为。该发布层级是工程负责人的产品决策，并经 `spec:AST-017` 的所有者 `cixzhang` 同意。已否决：将 `popover` 保留为默认值，因为这样手机上除非调用方主动选择，否则内联 combobox 会出现在软键盘下方（`component:Selector` 的 DEC-1 以同一理由否决了相同的默认值）。已否决：采用日期与时间字段的 `PickerPresentation` 取值集合并包含 `adaptive-bottom-sheet`（其原生选择器维度在此处没有对应物）。底部面板的各个部分不暴露 Tokenizer 的主题化目标；它们通过其组合的组件进行主题化。

底部面板界面是一个高模态 BottomSheet，由内联字段框内的触发器打开；它显示已选 token 并保留 `endContent`：顶部是带边框的搜索字段，复选框行在面板打开期间顺序固定，并在下次打开时按已选项优先重新分组，长列表渐进渲染，一个末尾带 Add 操作的创建行，以及一个固定的页脚，包含需确认的 Clear all 与 Save；各行编辑的是一份草稿，由 Save 提交（DEC-4）。该面板是由 `isOpen` 驱动的独立 BottomSheet。已否决：拆分出独立的管理面板与添加面板（两份近乎重复的列表；用户会失去自己的位置）。已否决：将这一个面板托管在 BottomSheetSwitcher 中。

**INV7 所有者例外**（`architecture:component-style-authoring` INV7；`spec:AST-017/FR60`），分为三部分，均超出 FR60/DEC-29 的允许范围——该允许范围只容许打开层多出五个元素、闭合控件不得多出元素——并按 FR60 的要求在此记录其测量计数。_`adaptive` 下的闭合字段。_ INV7 的界面预算规定，针对指针的呈现方式是在相同元素上改变属性与样式；而在紧凑粗指针客户端上使用 `adaptive` 时，闭合字段改为渲染不同的元素——持有触发按钮与已选 token 的字段框——以替代内联 combobox 输入框、其 token 移除操作以及其溢出处理，因为触摸界面是由按钮打开的底部面板，而不是锚定到输入框的菜单（DEC-3、FR16）。这一替换是移除元素而非增加元素：静止状态下，精细指针为 154 个元素，粗指针为 121 个，测量方式见下，因此粗指针在静止状态下仍低于精细指针的计数。_打开层。_ 打开的底部面板比它在精细指针下所替代的打开 popover 菜单拥有更多元素，因为它是一个不同的界面，而非同一界面的重新样式化：一个带面板与把手的全高模态、一个带清除操作的搜索字段、一个列表（其行为带指示器与位置的复选框行）、一个带 Clear all 与 Save 的页脚，以及面板自身的实时区域，替代了由普通选项组成的锚定 listbox；Clear all 确认仅在从按下 Clear all 起、到其关闭为止的期间存在于 DOM 中。在 Chromium 149 中于 Adaptive（默认）故事（已选五个 token）上测量 `body` 下的元素，精细 = 桌面 1280×800 `pointer: fine`，粗 = iPhone 13 配置文件 `pointer: coarse`。静止状态：精细 154 / 粗 121（带触发器与 token 的字段框，比带 token 移除操作与输入框的内联字段更小）。打开状态、查询为 "e"（搜索中状态）：精细 157——内联字段及其锚定菜单在该故事中唯一匹配 "e" 的条目上打开，加上首次播报所创建的两个共享页面实时区域——粗为 166。粗指针的合计值精确吻合：静止时 121，减去应用全局表面宿主的 2 个元素（打开的模态将 toast 宿主重新托管到自身内部，`spec:AST-003/FR18`），加上面板对话框的 47——BottomSheet 的对话框、面板、把手与边缘着色 7；面板主体 2；带清除操作的搜索行 19；列表 16（列表元素、其滚动宿主，以及两个复选框行各 7，含指示器与位置）；面板的实时区域 1；重新托管的表面宿主 2。待确认的 Clear all 在打开期间增加 20；页脚在每个状态下都固定（FR18），增加 9，因此在查询 "e" 时打开状态的粗指针计数为 175；任一界面变更时都会重新测量计数。强制 `bottom-sheet` 呈现方式在两种指针下渲染相同的元素（静止 115，在 "e" 时打开为 175，其对话框 62，其中创建行 6、固定页脚 9）。静止状态下粗指针的元素数量从不超过精细指针：在按下之前，面板的任何部分都不在 DOM 中。_自定义 token 的标签副本。_ 使用 `renderToken` 时，闭合的面板字段会为每个已选 token 额外渲染一个元素：一个持有条目标签的 `hidden` span，触发器的描述用它来替代调用方提供的 token 标记（AR6）。该副本位于无障碍树之外，因此其标签只被播报一次。在 Chromium 149 中于 Bottom sheet with end content and custom tokens 故事（四个 token）以 390px 测量：静止状态下 `body` 下 153 个元素，其中四个是这些副本，且每个标签在该故事的无障碍树中出现一次。该例外涵盖闭合的 `adaptive` 触发器、打开的面板以及自定义 token 副本；任一界面变更时都会重新测量其计数。

### DEC-4 — The sheet edits a draft that Save commits

**Reference:** `component:Tokenizer/DEC-4`

**Decider:** `imdreamrunner`, `2026-11-02`

面板编辑的是一份草稿：每次切换行、创建以及 Clear all 都改变面板所显示的选择，而 `value` 只改变一次，即 Save 通过 `onChange` 上报该草稿时，并以最后一次净编辑作为其 `change`（FR26）。草稿已变更时的关闭操作会在丢弃前询问；草稿未变更时直接关闭（FR27）。带 Clear all 与 Save 的页脚在每个状态下都固定在列表下方，因此用户搜索时这些操作不会消失；搜索字段是固定在列表上方的带边框输入框，因此该面板读起来像一个表单：一个字段、一个列表、两个操作。在触摸屏上，直接拖动结果会使焦点离开搜索字段而不清空查询，因此用户伸手去够的行会进入视野（键盘随之移动，`spec:AST-099`）。闭合的面板字段就是内联字段自身的框，因此在桌面使用内联字段、在触摸设备使用面板的页面只显示一个字段。已否决：每次切换都立即提交（误触会在用户看到结果之前就已生效，关闭时没有可丢弃的内容，而观察 `onChange` 的调用方会看到一连串部分选择）。已否决：仅在查询为空时显示页脚（Save 与 Clear all 恰好在用户开始输入时消失）。已否决：Done 关闭时不经过草稿（这样面板就无法放弃一次编辑）。已否决：拖动结果时清空查询（用户会失去为了到达那些行而进行的搜索）。
