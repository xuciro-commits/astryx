# Resizable component contract

## Contract at a glance

| Area                    | Contract                                                                                                                                                                                                                                                   |
| ----------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Public contract         | `useResizable`（尺寸、边界、折叠、吸附、持久化）与 `ResizeHandle`（`direction`、`position`、`isReversed`、`isDisabled`、`hasDivider`、`isAlwaysVisible`、`pillPlacement`、`label`、`resizable`、`children`），以及 `pixel()` 与 `percent()` 尺寸辅助函数。 |
| Behavior                | 该 hook 拥有区域的像素尺寸；Handle 是一个可聚焦的窗口分隔条，可通过指针和键盘调整其大小；LayoutPanel 渲染的窗格在折叠与展开时滑动。                                                                                                                        |
| End-user impact         | 人们通过拖动或键盘调整面板大小、折叠并恢复它，且尺寸会被记住，分隔条的移动方向与页面阅读方向一致。                                                                                                                                                         |
| Builder impact          | LayoutPanel 与 ResizeHandle 上的 `resizable` 可直接接收 useResizable 的输出，或像以前一样接收其 `props`（FR9）；LayoutPanel 的折叠无需改动代码即可滑动。                                                                                                   |
| Compatibility/readiness | `resizable` 也可接收 useResizable 的输出（FR9；patch `[feat]`）；其他 props 不变。正在折叠的 LayoutPanel 窗格会滑动并把焦点移出，然后变为 inert（FR8；`component:LayoutPanel` AR2）：patch，`[feat]` 滑动与 `[fix]` 焦点。实现缺口列在“当前状态影响”下。   |
| Review checks           | 拒绝丢失其分隔条角色、值或键的 Handle；拒绝逆阅读方向移动的箭头；拒绝会重新缩放的百分比默认值；拒绝已确定的状态、绘制、存储与 ARIA 相互不一致；存储保存最后一次确定的尺寸，并在拖动结束、取消或卸载时接收一次最终尺寸。                                    |
| Governing rules         | `spec:AST-010`；`spec:AST-020` FR15（APG Window Splitter）；`spec:AST-085`；`spec:AST-105` FR9；`architecture:interaction-modality`；`architecture:component-theming-surface`；`architecture:public-component-api`。                                       |

## Intent

Resizable 将 useResizable 状态与行为 hook 与可聚焦的 ResizeHandle 结合在一起。Handle 在放大的不可见 Grab 区域之上呈现默认的 Grip 胶囊。尺寸可以像素或百分比配置，而选定状态、持久化、回调、绘制与 ARIA 仍保持在已解析的像素上。

使用方的语法与示例属于 `Resizable.doc.mjs` 与 `useResizable.doc.mjs`。

## Compatibility and migration

- 保留已发布的默认值：`yes`；数字与精确的 `Npx` 是像素，精确的 `N%` 是一次性默认值，宽泛的 `defaultSize` 字符串类型保持源代码兼容。
- 兼容性类别：patch。`minSize` 与 `maxSize` 是边界 props，数值边界是像素。LayoutPanel 渲染的正在折叠的窗格现在会滑动（FR8，`[feat]`，在 `spec:AST-017/DEC-17` 下仅视觉变化），其内部焦点会移到它的 ResizeHandle，同时折叠的窗格变为 inert（DOM：`inert` 与 `aria-hidden`；`component:LayoutPanel` AR2，`spec:AST-017` FR53 下的 `[fix]`）。`resizable` 也可接收 useResizable 的输出（FR9，`[feat]`）；其他 prop、选项或返回成员不变。
- 受控/非受控行为：折叠可以受控（`isCollapsed`、`onCollapseChange`）或非受控（`defaultIsCollapsed`）；尺寸由 hook 拥有。
- 迁移决策：无。不支持类似 CSS 的 `min()` 与 `max()` 字符串；`percent(value, {min: pixel(value)})` 与 `percent(value, {max: pixel(value)})` 表示有边界的百分比。

使用方迁移说明属于使用方文档与发布说明。

## Current-state impact

- **Handle 方向未被反映（FR4）。** `Resizable.doc.mjs` 将 `direction` 列为 `resize-handle` 目标的视觉状态，但 Handle 并不反映它，因此针对某一方向的主题规则永远不会匹配，而 `architecture:component-theming-surface` INV6 要求声明的状态保留在拥有它的目标上。
- **窗口分隔条的缺口（AR1）。** 只有当调用方传入时，Handle 才用 `aria-controls` 指明它所调整的窗格；在没有百分比边界观察的容器中，无边界 Handle 不带 `aria-valuemax`；并且 End 不会移动无边界 Handle（`spec:AST-020` FR15）。
- **调用方的焦点与双击处理器会替换 Handle 的（FR7）。** 调用方 props 在 Handle 自身的 `onFocus`、`onBlur` 与 `onDoubleClick` 之后展开，因此传入其中任何一个都会使 Handle 的 focus-visible 胶囊和双击折叠失效，而 `architecture:public-component-api` INV7 要求处理器组合。
- **尚无 `collapsedLabel`（AR1）。** `createResizable` 与 `useResizable` 的 options 形式尚未构建，因此没有 provider 的调用方无法替换英文的“Collapsed”播报，而 `architecture:internationalization` INV3a 为其提供了按消息选项。
- **`shrinkOrder` 是惰性的。** useResizable 接收并记录 `shrinkOrder`，但没有任何代码读取它，因此它没有效果。

## Ownership boundary

**拥有**

- useResizable 的尺寸、折叠、吸附、持久化以及尺寸调整生命周期。
- ResizeHandle 的分隔符语义、指针与键盘交互，及其 `resize-handle` 目标。
- 默认的 Grip 胶囊及其 `resize-handle-pill` 目标，以及对齐的不可见 Grab 区域。

**不拥有 / 非目标**

- 被调整的区域——由 LayoutPanel、SideNav 或其他调用方拥有。
- 布局区域拓扑、inset、分隔条或滚动规则——由 `family:layout-regions` 拥有。
- Grab 区域的公共目标；不存在。

### Allowed variation

- **AV1 — 轴。** Handle 沿水平轴或垂直轴调整尺寸；分隔条的方向和光标随之变化。
- **AV2 — 放置。** Handle 内联就位或覆盖其父元素，而 Grip 胶囊位于起始、结束、居中或自动一侧。
- **AV3 — Grip 内容。** 调用方的 `children` 可以替换 Grip 胶囊，而不改变 Handle 或抓取区的归属。
- **AV4 — 分隔线。** Handle 可以绘制其分隔线；组合的区域会避免相邻的重复分隔线。
- **AV5 — 结构化百分比边界。** 描述符恰好携带一个 `min` 或 `max`，其值为 `PixelWidth`；普通百分比使用精确的 `N%`。

### Representative states

| 状态           | 必需的不变式                                     | 允许的变体               |
| -------------- | ------------------------------------------------ | ------------------------ |
| 默认手柄       | Handle、抓取区和 Grip 胶囊均渲染。               | 分隔线和始终可见的胶囊。 |
| 自定义手柄内容 | Handle 和抓取区保留；调用方内容替换胶囊。        | 调用方内容。             |
| 水平或垂直     | 交互沿轴进行；ARIA 方向为分隔条的方向。          | 尺寸、反转、胶囊放置。   |
| 已折叠         | `aria-valuenow` 为最小值，值文本为 "Collapsed"。 | 胶囊所在侧。             |
| 已禁用         | `aria-disabled`；不调整尺寸；保留 Tab 停靠点。   | 禁用态绘制。             |

### Transformation and precedence order

- **ORD1 — 解析。** 原子字符串精确解析；`percent()` 描述符是一个 0–100 的有限百分比，且恰好带有一个有限的非负像素边界。
- **ORD2 — 求值。** 百分比针对一个活动基准求值，然后应用描述符的下限或上限。
- **ORD3 — 提交。** 结构化默认值会作为像素提交一次；百分比边界保持实时，并用 `Math.min(max, Math.max(min, size))` 进行钳制，因此冲突时最大值胜出。

### Performance and resources

- **PR1 — 仅在需要时使用观察器。** 原子像素路径不增加观察器或渲染工作。结构化默认值只在所提供的容器上进行观察，直到其初始像素选择最终确定；持久化的像素会跳过该测量。百分比边界在实时期间复用共享的 ResizeObserver。校验与求值是常数时间，且不使用 CSS 解析器。

## Accessibility contract

- **AR1 — ResizeHandle adopts the APG Window Splitter pattern**（`spec:AST-020/FR15`），作为一个复合控件：Handle 是一个可聚焦的 `role="separator"`，带无障碍名称、`aria-orientation`（分隔条所沿的轴）、`aria-valuemin`、`aria-valuemax`，以及以像素为单位的 `aria-valuenow`，折叠时的 `aria-valuetext`，以及禁用时的 `aria-disabled`。`useResizable(handleRef, options)` 同样接受的 `CreateResizableOptions` 具有 `collapsedLabel?: string`，在折叠时作为 Handle 的 `aria-valuetext` 播报；缺省时使用目录中的 "Collapsed"（`architecture:internationalization` INV3a）。实现缺口：`CreateResizableOptions` 与 `useResizable` 的 options 形式尚未构建，因此 `collapsedLabel` 尚不存在。ArrowRight 与 ArrowDown 将分隔条移向其轴的末端，ArrowLeft 与 ArrowUp 移向起点，在 RTL 下内联箭头遵循阅读方向，配合 Shift 可加大步长，因此窗格会按其所在 Handle 的一侧增大或缩小；设置了吸附点时，箭头会移动到相邻的吸附点，超出 `minSize` 或 `maxSize` 的点按该边界计算（按住 Shift 时为两个）；Home 移动到最小尺寸，End 移动到最大尺寸；Enter 折叠可折叠窗格并恢复它，而使已折叠窗格增大的箭头会将其打开到高出其最小值一步的位置，或在其 `collapsedSize` 更大时打开到该尺寸（有吸附点时，打开到最接近该尺寸的吸附点；缩小的箭头则使其保持折叠）。无界的 Handle 报告一个测量得到的替代值作为 `aria-valuemax`：未提供容器时为其轴向上的窗口范围，或在百分比边界观测它时为其容器的内容框，绝不小于其当前尺寸，或在折叠时低于其最小值。`spec:AST-020/FR15` 下的实现缺口：Handle 仅在调用方传入时（SideNav 会传入）才用 `aria-controls` 命名其调整的窗格；位于没有任何百分比边界观测的容器中的无界 Handle 不携带 `aria-valuemax`，因为测量该容器会给一个边界全为像素的区域增加观测器（Performance and resources）；并且 End 不会移动无界 Handle。

## Decision log

### Structured percentages use a Table-style helper

**决策：** `percent(value, {min: pixel(value)})` 或 `percent(value, {max: pixel(value)})` 表示恰好带有一个像素边界的百分比。复用 Table 精确的 `pixel()` 绑定与 `PixelWidth`；不要创建并行的静态辅助函数。必填选项与 XOR 类型避免了普通百分比的第二种写法，并使每种受支持的组合都显式。该纯辅助函数可从服务端安全的 `Resizable/utils` 子路径获得，并使用相同的 `pixel()` 绑定，与 Table 既有的辅助函数/导出模式一致。`proportional()` 有意不复用，因为它表示同级权重，而不是字面百分比。

**已否决：** 解析递归的 CSS `min()` / `max()` 字符串。那会创建一套不完整的第二套 CSS 实现，而任意组合并无已证明的需求。

### The Handle is an APG window splitter

**决策：** ResizeHandle 已经作为一个复合控件运作，具备 splitter 的角色、值属性与键盘，因此它采用该模式所要求的各个部分及其键盘（AR1），并将调用方不传入的 `aria-controls`、在没有任何百分比边界观察的容器中施加于无界 Handle 的 `aria-valuemax`，以及无界 Handle 上的 End 键记录为实现缺口；内联方向键遵循阅读方向，因为让分隔条逆着它在屏幕上的移动方向移动的按键是一种缺陷。由 `cixzhang` 于 `2026-10-13` 决定。

**已否决：** 用单独的按钮折叠窗格；在 RTL 下使用无方向的 ArrowLeft。
