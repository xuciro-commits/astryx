# Calendar component contract

## Contract at a glance

| Area          | Contract                                                                                                                                                                                                                                                                                                                                                                                                     |
| ------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 公开契约      | `Calendar` 与 `CalendarProps` 从 `@astryxdesign/core/Calendar` 导出；`mode` 选择单个日期或日期范围，配合 `value`/`defaultValue`/`onChange`、边界、约束、跨度上限、焦点日期、显示选项，以及可选的 `calendar`（`CalendarSystem`）。每个值始终是公历 ISO 日期。公开的 `useCalendarDays` 与 `useCalendarNavigation` 钩子同样接受可选的 `calendar`（FR11）。                                                      |
| 行为          | 解析出的日历系统的一到两个月以日期网格的形式渲染在星期表头之下（DD1）；日期用指针或键盘选取；每个月网格至多持有一个漫游 Tab 停靠点，方向键、Home/End 与 Page 键按阅读方向移动它。Page 键按日历月步进，配合 Shift 时按日历年步进。                                                                                                                                                                            |
| 最终用户影响  | 键盘或屏幕阅读器用户会遇到一个具名的月网格，按日、周、月（配合 Shift 与 Page 键时按年）在其中移动，并听到每一天的名称、选中状态、今天标记与禁用状态，且使用的是应用所选的日历。                                                                                                                                                                                                                              |
| 构建者影响    | 可选：在 Calendar 或其 provider 上设置 `calendar`；对于需要 `Temporal` 的日历，在运行时缺少它时加载 polyfill。                                                                                                                                                                                                                                                                                               |
| 兼容性/就绪度 | `calendar` 属性是增量式的，默认值仍为公历。带 `-u-ca-` 关键字的 provider locale 会保持公历日期（`spec:AST-111` DEC-2）；设置 `calendar` 可另选一种。需要 `Temporal` 的日历在缺少它时回退为公历（`spec:AST-013` FR12 例外）。月份按钮在边界处使用原生 `disabled`，并在减少动态效果下缩放；被按键移动过的 Tab 停靠点可能变得陈旧；在最大的文字尺寸下 Calendar 会宽于手机屏幕；以上各点均列在当前状态影响之下。 |
| 审查检查      | 拒绝以下情况：日期网格没有 `role="grid"` 或没有名称；同一个月内有两个日期持有 Tab 停靠点；方向键不再跟随阅读方向；选中或今天状态仅靠颜色传达；星期表头被截断为固定字符数；表头行混用缩写名与短名。                                                                                                                                                                                                           |
| 管辖规则      | 星期表头由 DD1 规定；`architecture:public-component-api/INV1,INV5–INV8`；`architecture:component-theming-surface/INV3–INV7`；`spec:AST-020/FR15`；`spec:AST-085/FR1, FR4`；`spec:AST-102` FR4；`spec:AST-111` FR1–FR8、FR20、AR1；`spec:AST-013` FR12；`design:bidirectionality` DR6；`design:reduced-motion` DR1；`architecture:internationalization` INV8。                                                |

本表是审查用的投影；下文正文具有权威性。

## Intent

Calendar 让人通过查看整月来选取一个日期或一个日期范围。它拥有月网格、其导航、选中与范围语义，以及按日在其中移动的键盘模型；日期字段会组合它。

## Compatibility and migration

- 已发布的默认值是否保留：`yes` —— 在没有 `calendar` 属性或 provider 日历的情况下，网格显示公历月份 —— 但 DD1 例外：`no`，因为在缩写名可容纳的语言环境中（英语是其中之一），Calendar 会显示这些名称，且没有可保留短名的属性
- 兼容类别：增量式的可选 `calendar` 属性与钩子选项；默认值、导出与 DOM 结构均无变化；星期表头文本遵循 DD1。带 `-u-ca-` 关键字的 provider locale 会保持公历日期（`spec:AST-111` DEC-2）；设置 `calendar` 可另选一种
- 受控/非受控行为：`value` 配合 `onChange` 为受控；`defaultValue` 启动内部状态
- 迁移决策：无

使用方的迁移说明应放在使用方文档与发布说明中。

## Ownership boundary

**拥有**

- 月网格：其星期列头、周行、日期单元格、月外日期、周数，以及可变行数。
- 月导航、聚焦日期，以及移动它的键盘模型。
- 它所排布的日历月、它们的标签，以及在解析出的日历系统中的月与年步进。
- 单选与范围选中的语义、边界、约束与跨度上限。

**不拥有／非目标**

- 呈现 Calendar 的文本字段、弹出层与底部面板 —— 由 DateInput 及其同类组件拥有。
- 一天中的时间 —— 由 DateTimeInput 拥有。
- 日历解析与 `Temporal` 边界 —— 由 `spec:AST-111` FR1、FR2 与 FR5 拥有；日历运算 —— 由 `Temporal` 拥有。
- `handleRef`、`onFocusDateChange`、`min`/`max` 窗口内的初始月份、`weekStartsOn`，以及 `numberOfMonths` 的夹取 —— 已交付并由使用方文档与测试覆盖，此处除 FR1–FR7 外不作契约规定。

### Allowed variation

- **AV1 — 月布局。** 行数、月外日期与周数可随属性变化，而不改变 FR1–FR5。
- **AV2 — 内部状态。** 聚焦日期与选中状态可用任意私有形态存储。

### Transformation and precedence order

- **ORD1 — 选取。** 禁用检查 → 按模式更新选中 → `onChange`。
- **ORD2 — 焦点移动。** 按键 → 阅读方向映射 → 目标日期 → 必要时导航月份 → 焦点。

### Performance and resources

- **PR1 — 由渲染所拥有的网格。** 日期单元格由属性与状态渲染；焦点移动按需读取网格的单元格；日期按钮共享按压控制器的 window 与 document 监听器；Calendar 不拥有任何 observer。

## Accessibility contract

- **AR1 — 日期网格采用 APG Grid 模式**（`spec:AST-020/FR15`），作为一个组合控件：每个月是一个 `role="grid"`，具有可访问名称、星期 `columnheader` 单元格、周 `row`，以及日期 `gridcell`；后者在选中或位于范围内时携带 `aria-selected`，并持有由一个 `button` 以完整日期加上其选中或范围角色（选中、范围起点、范围终点或位于范围内）命名，该按钮为今天暴露 `aria-current="date"`，在禁用时暴露 `aria-disabled`；一个日期按钮持有 Tab 停靠点——`single` 模式下是选中日期（当其位于该月且可用时），否则是今天（当其位于该月且可用时），再否则是该月第一个可用日期；没有可用日期的月份没有 Tab 停靠点。实现缺口：一旦按键移动（方向键、Home、End 或 Page 键）放置了停靠点，之后的指针选取可能让它留在原处（当被选取的日期在网格中更靠后时总是如此），而当该月每一天都变为禁用时它会停留在被禁用的日期上。ArrowLeft 与 ArrowRight 按阅读方向移动一天（`design:bidirectionality` DR6），ArrowUp 与 ArrowDown 移动一周，Home 与 End 移动到该周第一个与最后一个可用日期，PageUp 与 PageDown 移动一个日历月，Shift+PageUp 与 Shift+PageDown 移动一个日历年（一项具名例外，如同 APG 日期选择器对话框；目标月缺少的日期夹取到其最后一天；FR9），Enter 或 Space 选取聚焦日期；方向键跳过被约束禁用的日期，并在同一方向上继续，必要时跨越月边界；目标落在 `min` 或 `max` 之外的方向键或 Page 键不产生任何变化，并将焦点保持在原处，对于方向上一年内没有可用日期的方向键也是如此；翻页到被约束禁用的日期时改为聚焦该月第一个可用日期，当该月没有可用日期时不产生任何变化。朗读的日期（日期按钮名称、网格名称与播报）使用网格所显示的日历（`spec:AST-111` AR1）。

### Theming anatomy

<!-- anatomy-theming:v1 -->

```json
{
  "Calendar root": {"target": "calendar"},
  "Month header": {"target": "calendar-nav"},
  "Day grid": {
    "none": {
      "reason": "reachability-gap: No current public target reaches the grid element itself; `calendar` paints the root and `calendar-day` the day buttons."
    }
  },
  "Day button": {"target": "calendar-day"},
  "Selected day": {"inherits": "calendar-day"},
  "Today marker": {"inherits": "calendar-day"}

```

`calendar` 由根元素携带，`calendar-nav` 由月份表头内的上一月与下一月按钮携带，`calendar-day` 由每个日期按钮携带。

## Family and system relationships

- `spec:AST-020/FR15` 决定组件采用哪些 APG 部件；日期网格采用 Grid 模式，因为它本就作为一个组合控件运作。
- `spec:AST-085` 拥有禁用状态下的可聚焦性；日期遵循它，而月份按钮不遵循（FR6）。
- `component:Button` 渲染月份按钮。
- `spec:AST-111` 拥有日历选择、受支持的日历、公历 ISO 值，以及 `Temporal` 边界；FR8–FR10 与 AR1 将其 FR4、FR6–FR8 与 AR1 投影到网格上。
- `component:DateInput`、`component:DateRangeInput` 与 `component:DateTimeInput` 把其字段文本所使用的日历传给其弹出层 Calendar（`component:DateInput` FR20、`component:DateRangeInput` FR6）。

### `spec:AST-013` FR12 exception — calendars that need `Temporal`

- **能力：** 公历、佛历、民国历与日本历之外的日历，它们需要运行时的 `Temporal`。
- **削减：** 在 `Temporal` 缺失或不支持该日历的地方（例如 macOS 与 iOS 上的 Safari），此类日历在首次渲染前解析为 `gregory`，并在开发环境中于服务端与浏览器各警告一次，指出 `temporal-polyfill/full/global`（`spec:AST-111` FR5）。加载了 `Temporal` polyfill 的应用会得到完整日历。没有 `Temporal` 的服务端渲染公历标记，而带 `Temporal` 的浏览器与之不匹配，因此服务端渲染的应用也要在服务端加载 `Temporal`。中国历与檀纪历的月份起始遵循运行时的 `Temporal`；服务端与浏览器的实现在某个月起始上不一致时，该月的渲染会不同，React 在注水期间会在客户端再次渲染它（`spec:AST-111` FR19）。在任何情况下，日期与月份名称都跟随网格所显示的月份与日期。
- **保留的义务：** `spec:AST-013` FR7 与 FR8，以及在中国历与檀纪历情形之外、服务端与浏览器以相同方式解析日历时始终成立的 FR9。公历网格保持主要任务、可访问性、公历 ISO 值与回调，以及重复使用；不会抛出任何异常；同时拥有 `Temporal` 或同时缺少它的服务端与浏览器渲染相同的标记。
- **证据：** 真实 Chromium 与 Firefox，分别在使用原生 `Temporal`、移除 `Temporal` 并加载 polyfill、以及移除 `Temporal` 且不加载 polyfill 的情况下；服务端渲染与注水分别在两侧都有 `Temporal`、两侧都没有、以及仅在浏览器中有的情况下。
- **所有者：** `nynexman4464`。
- **审查条件：** Safari 发布 `Temporal`。

## Current-state impact

- **最大文字尺寸下的宽度（FR2）。** 当文字尺寸接近主题尺寸的 275% 与 310% 时，例如浏览器默认字体更大（一旦文字跟随 Dynamic Type，即 iOS AX4 与 AX5），Calendar 会比手机屏幕更宽，因此只有横向滚动之后才能到达最后一个星期列。每一天仍然拥有自己的点按目标。
- **陈旧的 Tab 停靠点（FR3、AR1）。** 按键移动放置 Tab 停靠点之后，随后的指针选取可能把它留在原处（当被选取的日期在网格中更靠后时总是如此），而当该月的每一天都变为禁用时，它会停留在某个禁用日期上，因此 Tab 可能落在未选中或已禁用的日期上。
- **减少动效下的月份按钮（FR6）。** 当用户偏好减少动效时，Previous 与 Next 按钮在按下时仍会缩放，这与 `component:Button` FR15 的记录相悖，也不符合 `design:reduced-motion` DR1。
- **边界处的月份按钮（FR6）。** Previous 与 Next 在 `min` 与 `max` 处变为原生禁用，因此停留在到达边界的按钮上的键盘用户会丢失焦点，这与 `spec:AST-085` FR1 与 FR4 相悖。
