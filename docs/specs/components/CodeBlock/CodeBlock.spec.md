# CodeBlock component contract

## Contract at a glance

| 领域          | 契约                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| ------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 公共契约      | `CodeBlock` 与 `CodeBlockProps` 从 `@astryxdesign/core/CodeBlock` 导出；`code` 为必需项，其余已发布的 props 配置语言、头部、行呈现、复制、换行、尺寸、语法主题与折叠行为；`isDiff`（FR9）以调用方选择的形式在任意语言之上添加 diff 层；`endContent`（FR10）把调用方控件放在 Copy 旁边；`language` 接受内置标识符或语言值，每种较不常见的语言都是 `@astryxdesign/core/CodeBlock/languages/<path>` 下的独立模块，`createCodeLanguage` 用 tokenize 函数创建自定义语言（FR13）；`tokenizer` 已弃用。          |
| 行为          | CodeBlock 渲染一个只读代码面，在可用时应用语法高亮，为复制保留源字符串，并在不编辑内容的前提下提供可选的按行显示、头部、复制、调用方控件、主题与展开行为；没有任何控件覆盖代码，无头部的一行块（无标题、语言标签隐藏）读作一行（FR11）。复制图标通过 `code-block-copy` 组件图标槽解析，并带有已复制状态（FR15）。                                                                                                                                                                                         |
| 最终用户影响  | 读者可以查看并复制代码，理解可选的按行强调，并用键盘与辅助技术操作长示例或可折叠示例。无头部的块的读者永远不会遇到位于控件之下的代码，代价是控件所占的列宽；标签隐藏的一行命令读作一行，其控件就在旁边；产品操作位于 Copy 旁边，而不是块外。C、C++、SQL、Rust、Kotlin、Swift 与 Go 片段的读者看到的是高亮而非纯文本（FR12）；GraphQL、Java、Thrift、Objective-C、TOML、PowerShell、Ruby、Lua 与 Dockerfile 片段的读者也是如此，前提是产品传入了该语言的模块（FR13）。                                     |
| 构建方影响    | 构建方无需额外迁移或选择加入即可选用已发布的展示维度；diff 层是又一个可选维度，`endContent`（FR10）是他们自有控件的一个可选槽位，较不常见的语言是一次导入并作为 `language` 传入（FR13），而五个带默认值的语法主题槽位意味着无需为它改动任何语法主题。                                                                                                                                                                                                                                                     |
| 兼容性/就绪度 | 已发布的 `CodeBlock` API 保持稳定，唯一例外是 `tokenizer` 已弃用，改用自定义语言值（FR13）；其默认值保持不变，除下文“兼容性”中所述的无头部可见布局（FR11）与新增内置语言（FR12）之外；FR10（`endContent`，增量）与 FR11 为当前状态，等待实现；FR12（内置语言）、FR13（语言值，除 `tokenizer` 弃用外均为增量）与 PR4（其预算）为当前状态，等待实现；FR9（diff 层）为当前状态且已交付；Markdown 对 `diff` 围栏的默认路径遵循它（`component:Markdown` FR29）。FR15（复制图标槽，增量）为当前状态，等待实现。 |
| 审查检查      | 否决以下情形：丢失代码文本；复制经过变换的字符串；未命名的复制或展开控件；过期的展开状态/接线；丢失根 props/ref；主题目标偏离其绘制器；忽略有效溢出的视口可聚焦性；控件绘制在代码之上；调用方控件切换展开状态。                                                                                                                                                                                                                                                                                           |
| 治理规则      | `architecture:public-component-api/INV1,INV5–INV9`；`architecture:component-theming-surface/INV3–INV7,INV12`；`architecture:component-test-sufficiency/INV1–INV7,INV10–INV11`；`spec:AST-025/FR12–FR13`；`architecture:theme-tokens`（语法词汇与 diff 槽默认值）；`architecture:icon-resolution-and-component-slots/INV2,INV4–INV8`（复制图标槽）。                                                                                                                                                       |

本表是审查用的投影；下文正文仅在所有者批准后才具有权威性。

## Intent

呈现只读的独立代码或多行代码，并可选地提供语法、导航辅助、复制行为、有界滚动与可折叠展开，同时保留调用方的源字符串。

## Compatibility and migration

- 已发布默认值保留：是，但下文所述的无头部可见布局（FR11）与新增内置语言（FR12）除外
- 兼容性类别：兼容；`tokenizer` 已弃用但未移除，因此暂不需要任何 prop、导出、类型、默认值、目标或 ref 迁移
- 受控/非受控行为：折叠状态仍由组件持有，在适用时初始为展开，并在其控件消失时恢复为展开
- 可见默认值变更（FR11），非破坏性：无头部的块把其控件显示在代码旁专属于它们的列中，而不是覆盖在代码之上，因此其代码相应提前结束；按内容确定尺寸（`fit-content`）的块会增长该列的宽度，一行块读作一行。有标题或可见语言标签的块在任意行数下都保留其头部。无语言的 Markdown 围栏经默认代码路径采用它（`component:Markdown`）。由此不产生任何 prop、类型或目标迁移。
- 可见默认值变更（FR12），非破坏性：新增内置语言的块与 Markdown 围栏显示为高亮而非纯文本，且导出的 `tokenize`、`tokenizeAsync` 与 `tokenizeStreaming` 函数，以及调用它们的 RichText 代码块与编辑器，都会为这些标识符返回 token；文本、复制输出、标签与自定义 `tokenizer` 均不变，内置 tokenizer 在 PR4 预算内增长。Markdown 围栏通过其首个单词字符到达这些标识符（`component:Markdown` FR29）：`cpp` 围栏按 C++ 高亮，而 `c++` 围栏读作 `c`。
- 增量 API（FR13）：`language` 也接受语言模块，每个模块在 `@astryxdesign/core/CodeBlock/languages/` 下都有自己的子路径，且导出的 `tokenize`、`tokenizeAsync` 与 `tokenizeStreaming` 在原本接受语言标识符的位置也接受模块；在产品导入模块并传入之前，一切不变。
- 增量 API（FR14），当前状态，未经所有者审查：`startLineNumber` 设置源文件首行的编号；其默认值 1 保持已发布的行号栏与 `highlightLines` 语义
- 弃用（FR13）：已发布的 `tokenizer` prop 已弃用，但仍按发布时的行为工作；分阶段的 codemod 会在静态 `language="x"`（非 `plaintext`）旁把 `tokenizer={fn}` 重写为 `language={createCodeLanguage({name: 'x', identifiers: ['x'], tokenize: fn})}`，从而保留 `data-language="x"` 与 `x` 标签，并报告每一处它无法证明的用法（动态或缺失的语言、`plaintext`、展开运算符）；该 prop 仅在次版本发布时移除。
- 增量主题表面（FR15）：主题可以通过 `componentIcons['code-block-copy']` 映射复制图标；没有对应条目时，图标不变。
- 迁移决策：弃用 `tokenizer`，改用自定义语言值；在其移除之前不需要任何改动

使用方迁移说明属于使用方文档与发布说明。

## Ownership boundary

**拥有**

- 只读多行代码呈现，内置与自定义 token 渲染，行号与强调，头部/标题/语言呈现，复制行为与反馈，可选换行与有界滚动，可选折叠行为，语法主题组合，根 prop/ref 组合，以及已记录的 CodeBlock 主题目标。

- 语言值：`CodeLanguage` 承载什么，`@astryxdesign/core/CodeBlock/languages/<path>` 下的各语言模块，`createCodeLanguage`，以及每个用 CodeBlock 的 tokenizer 为代码着色的 Astryx 表面如何接受一个语言值，包括 Lab `DiffViewer` 的 `language` 与 `codeLanguages`（FR13）。

**不拥有 / 非目标**

- 散文中的行内代码——由 `component:Code` 拥有。
- 调用方提供的代码与语言标识符的含义、本地化或双向排序——由产品调用点与平台文本引擎拥有。
- 共享的有效滚动测量与焦点策略——由 `spec:AST-025` 拥有；CodeBlock 集成该能力，而不是定义一套并行的检测器。
- 代码的编辑、选择模型、校验、执行或持久化——由另一组件或产品调用点拥有。

### Allowed variation

- **AV1 — 语法绘制。** 内置 token 颜色、自定义 token 类型、CSS Highlight API 的使用、span 回退以及语法主题都可以在不改变源字符串或代码任务的前提下改变绘制。diff 行底色与其他任何语法绘制一样，是三个语法主题槽位：语法主题可以用其调色板协调它们，而不设置任何槽位的主题则保留默认值。
- **AV2 — 主题绘制。** 当前的 CodeBlock 目标可以在不改变文本、控件语义或归属的前提下改变其可接受的视觉属性。
- **AV3 — 代码内容。** 产品提供任意代码文本与匹配的语言标识符；CodeBlock 不解释程序的含义。

### Transformation and precedence order

- **ORD1 — 源。** 调用方代码字符串 → 行划分 → 内置或自定义分词 → 范围/span 绘制；复制始终消费原始代码字符串。
- **ORD2 — 头部。** 标题与符合条件的语言标签决定头部是否存在（FR3）；调用方控件其后是复制，存在头部时置于该头部，不存在时置于代码旁的角部控件组。
- **ORD3 — 样式。** 根主题目标与被反映的视觉轴 → 基础/容器/尺寸/动态样式 → 使用方 `xstyle`、class 与内联样式的组合。

### Performance and resources

- **PR1 — 分词。** 短代码可以同步分词；长的内置代码通过异步分词器让出，并在代码或语言改变时取消过期工作。
- **PR2 — 高亮生命周期。** 范围模式的高亮在其渲染的 token 集合改变或卸载时移除范围与可见性监听器。
- **PR3 — 大行集。** 大块可以分块渲染行并使用 content visibility，而不丢失源顺序或行身份。
- **PR4 — 语言预算。** 内置分词器（包含每一个 FR12 语法）压缩并 gzip 后保持在 4,608 字节以内，每个 FR13 模块压缩并 gzip 后最多给导入它的 bundle 增加 512 字节，对不导入它的 bundle 不增加任何字节；运行时没有任何加载，因此短代码在其首次渲染中即完成绘制（PR1），也没有任何块等待网络。

## Accessibility contract

- **AR1 — 具名控件。** 每个渲染出的复制与展开控件都具有非空的可访问名称，包括标题文本为空或仅含空白时。
- **AR2 — 展开。** 可折叠头部暴露展开状态与其受控区域，可通过指针、Enter 与 Space 切换，并使折叠的后代惰性，同时不移除受控区域。
- **AR3 — 复制反馈。** 复制成功会更新控件名称并发出一次本地化的 polite 播报；写入失败会发出一次本地化的 assertive 播报，因为它是错误（`spec:AST-086` FR5）；可见的用途仍可通过 tooltip 获得。
- **AR4 — 滚动访问。** 具名视口仅在存在有效溢出时进入 tab 顺序，并保留原生的 Arrow/Page 访问，依据 `spec:AST-025/FR12–FR13`。

## Decision log

### DEC-1 — Diff is a line layer over any language, tinted by three defaulted syntax-theme slots

**Decider:** `cixzhang`, `2026-10-12`

变更日志、迁移说明或评审意见的读者一眼就能看出添加了什么、删除了什么，同时仍能把代码当作代码来读：开启 diff 层后，行首的 `+`/`-` 列被单独放到一边，每行的其余部分保留基础语言的语法高亮，因此 `tsx` 的 diff 看起来就是带两类着色行的 `tsx`。这些着色属于语法涂色，因此它们位于语法主题中，即 `--color-syntax-added`、`--color-syntax-removed` 与 `--color-syntax-diff-header`，其旁边的边缘颜色为 `--color-syntax-added-marker` 与 `--color-syntax-removed-marker`，它们的默认值都由 `architecture:theme-tokens` 拥有；行号槽单元、行号与字形共享该行的色相，因为扫视边缘的读者应当在那里找到变化，而代码——每个 token 与每一段纯文本——保留语法主题的颜色，因此某个属性或标识符在变更行上与在上下文行上读起来完全一样；主题可以覆盖它们，以贴合自己的调色板。没有任何单一默认强度能让每个已发布预设的合格 token 在着色上保持高于下限、同时着色仍然可见——浅色页面主题下的深色预设会得到淡着色——因此该下限约束默认主题与覆盖主题，而预设的缺口是已知的，并被单独跟踪。区块头与文件头以柔和的行保持可见，使用语法主题自身的次要（标点）颜色——在默认主题中位于弱化色带上，在已定义主题中位于主题自身的背景上——这是常见 diff 渲染器给予它们的处理方式——因为围栏是作者的精确文本：涂色绝不改变它（FR1），复制也会原样往返；不想有头部的作者把它们留在围栏之外即可。一行 `--- `（包含其后的空格）只有在紧接 `+++ ` 行与 `@@` 行之前时才是文件头，因此以 `--` 开头的被删除行——包括紧邻下一个区块之前的 `---i;`——不会被误读，多文件 diff 也会保留每个文件头；该规则唯一无法区分的形态，是一行被删除的 `-- ` 紧接一行被添加的 `++ ` 以及一个区块头，它会被读作文件头，并被接受。Markdown 围栏仅在默认路径上通过其 info 字符串选择该层，因此自定义渲染器的契约保持不变。`+`/`-` 字形位于其自身的标记列中，与代码之间隔一个 token 的空隙，因此读者的目光在边缘处就能找到变化，代码的缩进也完全按书写的样子呈现。在着色行上，字形与行号占用该行的标记槽，因为字形是不依赖颜色的读者所依赖的线索，且它与它所标记的代码一起阅读；在默认主题中，标记槽默认使用主题自身的着色文本 token，这些 token 本就是为坐在着色表面上而制作的，而未设置它们的语法主题则保留自身的颜色——标记与头部文本使用其行号颜色，且头部不涂色——而不是借用页面主题的 token，因为在浅色页面下的深色预设中，那些 token 可能位于错误的极性上。已否决：从主题的 `string` 与 `tag` token 推导标记颜色（`tag` 为绿色的主题会把被删除行标成绿色）；把代码本身重新着色为行色相，无论是全部代码，还是只给没有 token 涂色的纯文本段（这会改变属性或标识符在行与行之间的外观）。对纯文本代码施加朝向行色相的浅着色，未获采纳。文本保留其语法颜色——语义文本颜色在其着色上会落到下限之下——而字形留在文本中，因此变化无需颜色即可读出，复制也完全一致。Markdown 围栏映射是 Markdown 自身的事实（其 FR29）；本记录只拥有该层。

每行带类型的底色（`highlightLines` 的已添加/已移除变体）不在此处决定：该层用 diff 文本本身来满足这一需求。在带高亮的变更行上，高亮会取代着色，因为两层半透明涂色会复合为没有任何主题选择的颜色，并把 token 推到下限之下。已否决：隐藏头部行（涂色会改变显示的文本并破坏复制；作者通过不在围栏中写头部来省略它们）；把 `diff` 作为独立语言（每一行都会退化为纯文本，代码便不再像代码一样可读）；只用语义 token 着色而不设语法槽（自定义语法主题无法让这些行与其调色板协调）；用 `--color-success`/`--color-error` 给变更文本上色（在着色行上低于 4.5:1 的文本最低对比度）；在组件 API 中使用按语言的 `diff-<lang>` 标识符（它们会成倍扩大语言列表；围栏约定改为映射到该 prop）；单独的 Diff 组件（围栏就是 CodeBlock，Markdown 已经把围栏路由到那里）。

### DEC-2 — Product actions are one caller-rendered slot beside Copy

**Decider:** `cixzhang`, `2026-10-24`

为代码片段提供第二种动作（例如在终端中运行命令）的产品，需要把该控件放在读者已经找到 Copy 的同一位置，而系统需要在不必了解产品动作的前提下做到这一点。`endContent` 就是那个位置：调用方渲染自己的控件，并拥有它们的名称、状态与动作，CodeBlock 只负责定位它们，按阅读顺序放在 Copy 之前，因此在每个块中 Copy 都保持为行内末端的最后一个控件。该名称沿用 Dialog 与 Drawer 的头部 end-content 槽，它在那里承载相同的含义。调用方控件永远不会创建头部，因为头部的存在是为了承载代码片段的上下文，而没有上下文的块会使其控件留在角落簇中。已否决：声明式的 `{label, icon, onClick}` 动作列表（CodeBlock 会渲染它并不拥有的控件）；为每种产品动作提供一个 prop。

### DEC-3 — Controls take their own column, so a headerless one-line block is one row

**Decider:** `cixzhang`, `2026-10-24`

涂在代码之上的控件会遮住读者的文本，因此无头部的块把控件放在它们自己的行内末端列中，位于代码视口旁边，宽度与控件本身相同；该列贯穿块的整个高度，因为滚动框会把它的行裁剪为一个矩形。把该列在首行上居中，会让无头部的一行块读作一行且间距均匀，并在块逐行增长时保持控件不动，因此流式块永远不会移动它的控件。单行模式是隐藏语言标签的既有选择：显示标签的调用方在任意行数下都保留头部及其上下文，而隐藏标签的调用方则得到那一行。该列没有宽度上限；调用方提供少量图标控件，代码视口占据其余空间。已否决：把可见标签折进一行块（标签是调用方选择显示的上下文，而当标签回到头部时，流式块会移动其代码）；只在首行预留空间（被滚动的行仍会跑到控件之下）。

### DEC-4 — A native language set chosen by use; every other language is its own module, passed as the language

**Decider:** `cixzhang`, `2026-10-25`

对于人们写得最多的语言，读者在首次渲染（PR1）时就能看到短代码片段被高亮，无需任何产品配置：原生集合是 CodeBlock 已经认识的 11 个语言族，加上 C 与 C++、SQL、Rust、Kotlin、Swift 与 Go，它们合起来覆盖了大型工程 Markdown 语料中指名语言的围栏的约 97%，且落在每个使用方都要付出的 4,608 字节预算之内。其他每种语言都按一次一种的方式选择性启用：产品导入该语言的模块，并在语言所在的位置传入它，即 CodeBlock 或 Lab 的 `DiffViewer` 上的 `language`，或在只看到一个围栏的词或一个文件名的表面上通过 `codeLanguages` 传入，因此指明语言的取值也携带渲染它的东西，而 bundle 只包含它导入的语言。产品自己编写的语言也是同类取值，由它自己的 tokenize 函数构成，因此一个概念就覆盖了所有语言，而单独的 `tokenizer` prop 已弃用；Astryx 模块保持不透明，因此它们的语法格式保持内部。已否决：上下文提供者（渲染块的方式会取决于它所在的位置，而不是它的 props）；语言包或分组导出（产品会选择性启用它从不展示的语言）；内置每个语言族（每个使用方都为长尾付出代价）；全局注册表（状态在多个 React 根与请求之间共享）；按需加载语法（块会先以纯文本绘制，再重新着色，并等待网络）。
