## Intent

Schedule 从调用方拥有的数据源渲染事件，围绕受控日期所属的范围，呈现为月网格、周或日时间网格，或列表。它拥有带时区感知的日期运算、通过头部插件进行范围翻页、带挂起回退的异步加载，以及每个视图内部的事件布局。时间网格是几何承载含义的视图：事件的垂直范围是其时长，它在日列中的水平份额是同时发生多少件事，视口的滚动位置是使用者正在看一天的哪一部分。本记录确定这三项几何契约，以及时间网格视图对事件提供的唯一交互：视图拥有的弹出层，内容由调用方提供。月视图给每个周行一个高度；本记录确定繁忙的一天如何在不丢失事件的前提下容纳其中，并且月视图提供与时间网格相同的事件弹出层。交互是视图的属性，而不是 Schedule 的属性。

## Compatibility and migration

- 保留已发布的默认行为：尚未作为稳定版发布；该组件随实验性的 `@astryxdesign/lab` 包发布。
- 兼容类：附加。时间网格视图选项 `renderPopover` 是可选的，默认不存在。时间网格的默认行为在四个方面发生变化，且任何调用方都无法通过 API 观察到：范围包含今天时的初始滚动位置；同时发生事件的并排摆放；一个滚动所有者配合粘性头部、全天行和刻度槽；以及时长 24 小时或更长的定时事件作为全天行中的跨越条。月视图的默认行为在三个方面发生变化：其可访问结构是表格而非只读网格；事件超过三层的一天显示两个 chip 和一个“+N more”按钮；chip 先显示标题再显示时间。
- 受控/非受控行为：不变。`date` 通过 `onChangeDate` 保持完全受控；Schedule 不持有选择状态。
- 迁移决策：无需迁移（DEC-1 至 DEC-6 是附加的或内部的）。

使用方迁移说明属于使用方文档与发布说明。

## Ownership boundary

**拥有**

- 从 `view` 和 `date` 解析出待渲染范围，将事件源过滤并排序到该范围，并在加载器挂起期间保持挂起。
- 时间网格几何：单一滚动视口、粘性头部、全天行与小时刻度槽、小时槽、当前时间线，以及定时事件与全天事件在其日列中的摆放，包括同时发生的事件如何共享一列，以及哪些定时事件是全天行中的跨越条。
- 每个待渲染范围下时间网格视口的初始滚动位置，并在挂起回退与已加载内容之间记住使用者对该范围的滚动偏移。
- 周视图与日视图中的事件弹出层：当视图用 `renderPopover` 构建时，每个有内容的已绘制事件块都是视图渲染的原生按钮——其位置、绘制、内容、可访问名称、DOM 顺序、局部焦点提升和 popup 属性——并且视图拥有这些按钮所打开的唯一 Popover：其实例、哪个事件处于打开状态、其锚点、其对话框名称、其标准表面与内边距，以及何时关闭。
- 当视图没有 `renderPopover` 时，向辅助技术宣告时间网格结构的隐藏只读网格。
- 月视图的表格结构与事件布局：其表头与单元格名称、每个周行中的 chip 层级、三层上限、繁忙一天上的“+N more”计数，以及那个显示繁忙一天的事件、或在 `renderPopover` 下显示单个事件内容的弹出层——其实例、当前打开的内容、其锚点、其对话框名称、其标准表面与内边距，以及何时关闭。

**不拥有 / 非目标**

- 弹出层的内容：事件详情说了什么、它们的加载与错误，以及其中的任何操作或链接——由产品调用点通过 `renderPopover` 拥有。调用点绝不会收到触发 prop、打开状态或弹出层实例。
- 除周、日、月视图的事件弹出层以及月视图的日弹出层之外的任何交互——导航、菜单、编辑、选择、拖拽——在本记录中不是 Schedule 的概念。
- 列表视图与自定义视图中的事件交互——每个视图拥有自己的交互契约；Schedule 及其上下文不携带任何视图的激活回调。
- 弹出层本身的对话框语义、关闭、焦点移动和表面内边距——由 `component:Popover` 拥有；时间网格与月视图用其默认值组合该组件，且不暴露它的任何 prop。
- 事件创建、移动、调整大小或拖拽——不是 Schedule 的概念。
- 同时发生事件之间的排序或优先级；在布局中不会偏好任何事件。
- 翻页控件与视图切换器——由头部插件拥有。
- 任何浮于页面之上的内容的跨表面堆叠——由 `architecture:layer-runtime` 拥有；Schedule 不在顶层绘制任何内容。
- 键盘滚动机制、滚动链和原生滚动条呈现——由 `spec:AST-025` 拥有；Schedule 通过共享的滚动 hook 参与。

### Allowed variation

- **AV1 — 小时窗口与密度。** 调用方选择 `minHour`、`maxHour` 与 `hourHeight`；FR4 的提前量随 `hourHeight` 缩放，FR3 的对齐对任意窗口都成立。
- **AV2 — 容器高度。** 时间网格默认高 640px，并会收缩到更短的 Schedule 根；视口是框架头部之下剩余的任何部分，FR4 的限制跟随测得的高度。
- **AV3 — 列最小值。** 日期列至少 140px 宽，并均分剩余宽度；更窄的视口在 FR1 下沿行内轴滚动，而不是挤压列。
- **AV4 — 簇宽度。** 簇中的块均分列；能扩展到空闲列的块会扩展，因此同一簇内宽度不同，但不改变任何人的顺序。
- **AV5 — 事件按钮样式。** 获得焦点或悬停的事件按钮可以在其列内上升并显示焦点环；主题通过共享焦点令牌改变该环。打开事件的按钮携带 `aria-expanded="true"`，因此主题可以从渲染出的属性为打开状态设置样式。
- **AV6 — 月 chip 时间。** 月 chip 的时间能否放在其完整标题旁边取决于渲染出的文本，因此它随语言环境、主题的字号阶与列宽而变化。

### Transformation and precedence order

- **ORD1 — 定时布局。** 将每个事件裁剪到可见小时窗口 → 强制十五分钟最小值 → 排序（开始升序、结束降序、`id` 升序）→ 分配簇 → 首次适配分配列 → 将每个块扩展到后续空闲列 → 转换为列分钟与宽度的百分比。
- **ORD2 — 初始位置。** 在范围键的首次布局时：若该键有记忆的偏移则恢复它；否则 FR4 根据当前时间线计算偏移并限制它；偏移在绘制前同步赋值。人员之后的滚动会覆盖记忆的偏移；其他任何行为都不会。
- **ORD3 — 固定。** 粘性表头单元格绘制在列之上，栏槽绘制在列之上，角单元格绘制在两者之上，全都作为孤立视口内的局部顺序。
- **ORD4 — 月布局。** 对事件排序（第一天、全天与多天优先、覆盖更多天优先、更早开始、标题、`id`）→ 按该顺序，为每个事件在它覆盖的每一周赋予在其于该周所有天都空闲的最低层级 → 对每个有位于第四层或更高事件的日期，将其第三层交给“+N more”，并统计该天位于第三层或更高的事件 → 绘制剩余 chip，在被计数的那几天周围切分跨度。

### Performance and resources

- **PR1 — 每个范围一次测量。** FR4 在布局 effect 中每个范围键测量视口一次；不为定位添加 `ResizeObserver`、定时器或滚动驱动的重新渲染。记忆偏移在视口生命周期内使用一个被动滚动监听器。
- **PR2 — 纯布局。** 簇与列分配是该天事件与小时窗口的纯函数，不读取 DOM，并在渲染期间运行。
- **PR3 — 共享观察者。** 键盘所有权与溢出状态来自共享滚动 hook；Schedule 不添加自己的观察者。
- **PR4 — 纯月布局。** 层级分配与“+N more”计数是范围事件与日期的纯函数，不读取 DOM，并在渲染期间运行。
- **PR5 — CSS 中的 chip 适配。** 月 chip 的时间能否放在标题旁边由布局决定，绝不在脚本中测量。

## Accessibility contract

- **AR1 — 可达的视口。** 时间网格视口是 `spec:AST-025` FR12 下的键盘滚动所有者：仅当某个轴溢出时它才处于 Tab 顺序中，暴露 `role="region"`，其名称由渲染出的范围标题后接 "time grid" 构成，原生方向键与 Page 键可以滚动它。它的键盘焦点环是一个指针穿透的覆盖层，在视口之后绘制，位于边框裁剪所及的边缘之内，因此焦点环的每条边都显示在固定的表头与刻度栏之上。溢出消失不会移动焦点。
- **AR2 — 具名的事件按钮。** 使用 `renderPopover` 时，每个按钮的无障碍名称依次是事件的标题、它的时间范围（或 "all day"）、它的分类标签，以及完整日期：可见文本在名称中居前，而之所以加上日期，是因为按钮是单独被到达的，而不是位于某个带日期的单元格内。时长 24 小时或以上的跨度，其时间范围携带起点与终点的日期。在隐藏的只读网格中，每个全天单元格以标题、分类标签，以及带日期的起点与终点来命名这样一个跨度。
- **AR3 — 可见焦点与弹出层语义。** 获得焦点的事件按钮在其日期列内完整显示共享焦点环；它在局部抬升到相邻块之上，使焦点环绝不会被后来的兄弟元素裁剪。每个事件按钮带有 `aria-haspopup="dialog"`、仅当其事件打开时才为 true 的 `aria-expanded`，以及命名该视图弹出层的 `aria-controls`。弹出层是一个以事件标题命名的模态对话框；打开时焦点移入其中，关闭时返回到打开它的按钮，遵循对话框模式。
- **AR4 — 装饰性部分保持静默。** 表头单元格、小时标签、小时槽位、全天单元格网格以及当前时间线均各自对辅助技术隐藏；绘制出的视口本身则被暴露，使其 Tab 停靠点以及（使用 `renderPopover` 时的）按钮可达。使用 `renderPopover` 时，日期列把它们的按钮与静态块归组在以完整日期命名的 `role="group"` 下，全天行归组在以 "All-day events" 命名的 `role="group"` 下；不使用它时，各列与全天行整体隐藏。
- **AR5 — 只读网格保留。** 不使用 `renderPopover` 时，隐藏的只读 `grid`（带 `aria-readonly`、按天划分的列标题、按小时划分的行标题，以及列出每个事件无障碍标签的单元格）即时间网格的无障碍表示，且其中不含任何可聚焦元素。
- **AR6 — 方向与动效。** 固定、列顺序与块偏移使用逻辑属性，并在从右到左方向下镜像。初始定位是即时的，因此减少动效偏好没有需要抑制的内容。
- **AR7 — 月表格与 "+N more"。** 月视图是一个表格，而非交互式网格：它以月份标题命名，星期几是它的列标题，每个周行有一个命名其日期的行标题，每个单元格以完整日期命名。一个角列标题位于行标题列之首，因此每一行都有相同的列，且每个日期单元格的列标题就是它的星期几。该表格不作方向键导航的承诺；某一天的 "+N more" 是阅读顺序中的一个普通 Tab 停靠点。该按钮的无障碍名称是计数与完整日期（"2 more events, Tuesday, October 6, 2026"；单个隐藏事件读作 "1 more event, …"）。它带有 `aria-haspopup="dialog"`、仅当其日期打开时才为 true 的 `aria-expanded`，以及命名该视图弹出层的 `aria-controls`，并完整显示共享焦点环。弹出层是一个以完整日期命名的模态对话框；打开时焦点移入其中，关闭时返回到该按钮。当按钮不再渲染时，焦点移到该日期的单元格，该单元格以编程方式获得焦点而不进入 Tab 顺序，并显示共享焦点环。该单元格的隐藏事件列表持续命名当天的每个事件，因此屏幕阅读器用户无需打开即可听到整天内容。
- **AR8 — 月事件按钮。** 使用 `renderPopover` 时，chip 按钮的无障碍名称依次是事件的标题、它的时间范围（或 "all day"）、它的分类标签，以及它的日期——完整日期，或对于跨多天的 chip 而言其日期范围。某天列表中的行按钮以同样的方式命名，并带完整日期。chip 在周中其首日之后覆盖的单元格，用从不获得焦点的静态文本来命名该事件：它的标题、它的时间范围（或 "all day"）、它的分类标签，以及 chip 起始的完整日期前的 "since"。获得焦点的月事件按钮完整显示共享焦点环，并在局部抬升到相邻 chip 之上。

**引用：** `component:Schedule/DEC-1`

**决定者：** cixzhang, 2026-10-04

交互属于视图，因为事件是什么、如何到达它，在时间网格、月单元格、列表行与自定义视图之间各不相同。Schedule 及其上下文不携带任何激活回调。周视图与日视图共享一个选项 `renderPopover(event)`，并拥有环绕它的一切：原生事件按钮及其弹出属性、唯一的 Popover 实例、哪个事件处于打开状态、锚点、对话框名称、关闭、焦点返回，以及事件离开网格时的关闭。调用方为某个事件返回内容，或返回 `null` 使该事件保持只读，除此之外不接收任何内容。缺少该选项时，网格是只读的。月视图与列表视图在此没有交互选项；各自在自己的记录变更中采用自己的选项。

已否决：在 Schedule 上或上下文中提供激活回调——一种模型无法适配每个视图，且与视图拥有的 ARIA 并存的回调可能相互矛盾。已否决：围绕视图的触发元素组合一个由调用方拥有的表面——视图无法知道自己与什么组合，且两个所有者会写同一个按钮。已否决：提供替换事件内容的渲染属性——它把颜色、过去时间变暗以及时间格式化推入每个产品。

### DEC-2 — Simultaneous events share the column side by side

**引用：** `component:Schedule/DEC-2`

**决定者：** cixzhang, 2026-10-04

并发通过宽度呈现，绝不通过绘制顺序：重叠簇把它的列拆成相等的轨道，块扩展到后续的空闲轨道，且任何块都不会被覆盖，因此没有需要暴露的等级，块之间也没有 `z-index`。簇内的顺序由开始时间、长度与 `id` 固定，这使布局仅由数据决定。

已否决：采用层叠方式，每个较晚的层级内缩并抬升到前一层之上——因为较晚的块会遮住较早块的标题，且顺序取决于输入顺序。

### DEC-3 — A range containing today opens one hour before now, once

**引用：** `component:Schedule/DEC-3`

**决定者：** cixzhang, 2026-10-04

视口在人们注意力所在之处打开：把当前时间之前的一小时置于顶部，并钳制在网格之内。对人们打开的每个范围，它只这样做一次，随后便不再干预滚动，包括跨越挂起回退的整个过程，因此无论是迟到的加载器还是时钟滴答都无法移动他们正在阅读的内容。组件从时钟与范围推导这一点，因此没有属性来选择它。

已否决：提供 `initialScroll` 属性——因为尚未展示出两个在其他方面相同的日程之间由调用方拥有的区分。

### DEC-4 — One scroll owner with sticky header, all-day row, and gutter

**引用：** `component:Schedule/DEC-4`

**决定者：** cixzhang, 2026-10-04

表头、全天行、刻度栏与各列都是同一视口内同一网格的条目，用 `position: sticky` 固定，因此它们的轨道是同一些轨道，滚动条、缩放级别或行内滚动都无法把它们分开。视口保留自己的滚动条槽，并且是键盘滚动所有者。

已否决：把表头放在视口之外、靠滚动同步或脚本化的滚动条宽度常量保持对齐——因为它在任何未经测量的滚动条呈现下都会漂移。

### DEC-5 — The event popover is a standard Popover with no presentation options

**引用：** `component:Schedule/DEC-5`

**决定者：** cixzhang, 2026-10-04

事件弹出层就是采用其默认值的 `component:Popover`：由事件标题命名的对话框角色、模态、自动聚焦、回退关闭、Escape 与轻触关闭、标准表面与内边距。该视图选项不暴露任何 Popover 属性——没有内边距、位置、宽度、关闭方式或受控状态——也没有关闭或控制参数，因此内容保持语义化，视图可以在不改变选项的情况下改变呈现弹出层的方式。弹出层在每种指针类型与宽度下都按弹出层呈现。

已否决：提供内边距或满版式的逃逸——未来需求是本记录上一个单独的呈现决策。已否决：在内容函数旁边提供配置对象——不存在第二个不可分离的选项。

### DEC-6 — A busy month day shows a count that opens the whole day

**引用：** `component:Schedule/DEC-6`

**决定者：** cixzhang, 2026-10-06

每个月周行保持同一高度，最多绘制三层 chip。当某一天需要更多时，它的第三层变成一个 "+N more" 按钮，统计未在那里绘制的事件，并打开该视图唯一的弹出层，后者列出那一天的所有事件。没有事件被丢弃，也没有任何内容绘制到其行之外；每单元格的隐藏列表为辅助技术保留整天内容。布局由数据推导，因此没有属性来选择它。

已否决：让行增高以容纳内容——高度不同的各周不再读作一个网格，并把后面的周推出视野。已否决：不打开任何内容的计数——隐藏的事件对视力正常的用户仍不可达。已否决：切换到日视图的 "+N more"——它需要在 Schedule 上有激活回调，而 DEC-1 将其排除在外。

### DEC-7 — The month view offers the time grid's event popover

**引用：** `component:Schedule/DEC-7`

**决定者：** cixzhang, 2026-10-06

月视图采用与周视图和日视图相同的 `renderPopover` 选项，并拥有同类弹出层：一个实例，从视图渲染的原生按钮打开，以事件标题命名，内容仅为调用方提供的内容。chip 按钮位于 chip 起始的那个单元格内，因此月视图在两种模式下都保持同一表格结构，且按钮替代单元格的隐藏列表，使每个事件只被播报一次。日期弹出层就是同一个实例：繁忙日期的列表以一次手势把某个事件交给它，焦点返回到该日期的 "+N more"。当它的某个事件处于打开状态时按下那个 "+N more"，会在同一手势中再次显示该日期的列表；这种返回是有意为之的，弹出层本身不保留回退步骤。

已否决：当选项存在时用分组替代表格——月视图保持一种无障碍结构。已否决：在日期列表之上再叠一个弹出层——两个模态对话框会叠加焦点陷阱与关闭逻辑。

### DEC-8 — A timed event of 24 hours or more is an all-day span

**引用：** `component:Schedule/DEC-8`

**决定者：** cixzhang, 2026-10-06

在周视图与日视图中，持续 24 小时或更久的定时事件是全天行中的一个跨度，与仅有日期的事件相同，而不是每个日期列中的块。那么高的块不会告诉人们跨度未告诉的任何信息，而且它会在那些天占用每个重叠簇的一条轨道。阈值按事件自身的时间瞬间衡量，因此不依赖小时窗口或时区的日长。

已否决：把每个跨午夜的事件移到全天行——一场在午夜之后结束的深夜会议属于它所占据的那些小时。
