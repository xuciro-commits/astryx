## Intent

ChatVirtualizer 让包含数千条消息的对话记录只占用大约一个视口的 DOM 开销。它拥有开窗及其位置。向辅助技术投递新消息、浏览器的滚动锚定规则，以及手指滚动监视，都留在各自的所有者处。

## Compatibility and migration

- 已发布默认值保持不变：`yes`（新的 Lab 组件）
- 兼容性类别：增量式实验性
- 受控/非受控行为：不适用
- 迁移决策：无

## Ownership boundary

**拥有**

- 哪些行被挂载、代表其余行的占位元素，以及它恢复的滚动位置（跟随末尾或某行标识）。
- 在窗口移离某行时，让持有焦点的行保持挂载。
- 通过 Core 的 `useScrollableArea` 为其自身滚动容器提供键盘访问。

**不拥有 / 非目标**

- 浏览器的滚动锚定规则：列表仅通过 Core 的滚动锚定写入器关闭锚定，该写入器是此规则的唯一所有者。
- 区分手指滚动与程序滚动，以及它何时结束：Core 的 `useFingerScroll` 决定这两者；在该滚动持续期间，列表暂缓其 scrollTop 写入。
- 向辅助技术投递新消息：由 `ChatMessageList` 的 `role="log"` 投递（`spec:AST-086` FR1）。

## Accessibility contract

- **AR1 — 键盘访问。** 在 own-container 模式下，滚动容器是一个 `group`，由列表的 `label` 命名，否则使用翻译后的 “Messages”，键盘用户可以聚焦并滚动它（`spec:AST-025` FR12）。在 attach 模式下，调用方的滚动容器拥有此项。
- **AR2 — 历史不是新消息。** 挂载并非新消息的行的提交（窗口在历史上移动，或历史在上方加载）会将内容块标记为 `aria-busy="true"`，直到其后的那一帧，因此日志不会将这些行作为新内容读出。追加在末尾的消息以未标记状态挂载，由日志投递它。
