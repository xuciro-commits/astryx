# PowerSearch component contract

## Intent

PowerSearch 通过字段、运算符和值的选择提供结构化筛选。其编辑器浮层让正在进行的编辑任务在窄搜索栏和宽搜索栏上都保持可读。当编辑器能够跟随 PowerSearch 的宽度时，它与该外表面保持对齐。当 720 CSS px 的可读性上限使编辑器变窄时，它停留在打开它的那个稳定控件附近，而不是横跨页面，也不依赖输入模态。

PowerSearch 还提供触摸呈现方式，它是紧凑粗指针屏幕上的默认方式（DEC-3）：整个字段变成一个触发器，显示仅用于展示的筛选标记，筛选工作则移入一叠高耸的模态底部抽屉——Filters、Add filter 和一个值步骤，每个都在引导它出现的那个抽屉之上打开，也各自被关闭并返回该抽屉——这套流程在紧凑触摸屏上可读，且不会被软件键盘遮住编辑器。在精细指针下，或在不紧凑的屏幕上，字段保留 tokenizer 和编辑器浮层，而 `presentation="popover"` 在所有设备上都保留它们。DEC-3 规定了该流程的形态。

在已发布的 PowerSearch 尚未满足某项要求的地方，相应条目会带有一条用现在时表述的实现缺口说明。

## Compatibility and migration

- 已发布的默认值保持不变：锚定到宽度超过 720 CSS px 的 PowerSearch 的编辑器浮层为 `no`；其他宽度保持当前的尺寸行为。
- 兼容性类别（DEC-1、DEC-2）：有意的默认布局与位置变更，且无公共 API 变更。DEC-3 新增稳定的 `presentation` prop 及其 `adaptive` 默认值，正如下面两条 DEC-3 条目所述。
- 受控/非受控行为：不变。
- 日历：日期值遵循提供方的日历。带 `-u-ca-` 关键字的提供方区域设置保留公历日期（`spec:AST-111` DEC-2）；设置提供方的 `calendar` 即可选择某一种日历。
- 迁移决策：`component:PowerSearch/DEC-1`、`component:PowerSearch/DEC-2`，以及针对 `adaptive` 默认值的 `presentation="popover"`（见下文）。
- 稳定呈现方式（DEC-3）：`presentation` 是一个新的稳定 prop。该 API 变更是增量式的：这个 prop 是新增且可选的，没有移除或收窄任何既有的 prop、类型或导出。抽屉呈现方式不新增任何主题化目标。
- 默认值变更（DEC-3）：`presentation` 默认为 `adaptive`，这改变了已发布的 `popover` 默认值。在精细指针下、在不紧凑的屏幕上、在服务器上、以及在水合过程中，没有 `presentation` 的字段会与之前完全相同地渲染 tokenizer 字段和编辑器浮层（`spec:AST-017/FR59`）。在紧凑的粗指针屏幕上，它渲染触发器与抽屉流程（FR11–FR21）：筛选通过堆叠的抽屉添加和编辑，而不是通过 typeahead 和编辑器浮层；筛选在其值步骤确认时提交；`menuWidth` 和 `tokenOverflowBehavior` 没有可作用的对象。行为仅在那里改变，这正是 `adaptive` 的用途。`presentation="popover"` 在所有设备上恢复先前的呈现面——即恢复输入 `spec:AST-017/DEC-23` 与 `architecture:public-component-api/INV16` 所指出的那个。没有 codemod 会添加它，因为向每个 PowerSearch 添加它都会让每个调用方退出新的默认值。稳定的 prop 与这个默认值以 `[feat]` 一起在补丁版本中发布：该发布层级是工程负责人的产品决策，并需取得 `spec:AST-017` 负责人的同意（DEC-3）。
- 与 DEC-3 一并的一项稳定修复：在 StrictMode 下，挂载时不播报结果数量（FR19）。它符合 `spec:AST-017/FR5` 下的 `[fix]`：它恢复了所记载的契约（只播报挂载之后的变更），没有 `onChange` 值、prop 或渲染文本发生变化，也没有任何有效的使用方必须改动。它作为单独的 `[fix]` 补丁版本发布。
- 第二项稳定修复：在 `popover` 呈现方式下，在空输入上按 Backspace 不会移除只读字段的任何筛选（FR22）。它符合 `spec:AST-017/FR5` 下的 `[fix]`：它恢复了所记载的 `isReadOnly` 契约，即“阻止添加、编辑或移除筛选”，没有 prop、`onChange` 形状或渲染文本发生变化，也没有任何有效的使用方依赖只读字段丢失筛选。它作为 `[fix]` 补丁版本发布。
- 第三项稳定修复：在 `popover` 呈现方式下，Clear all 保留只读筛选，在第一个被移除的索引处报告 `remove`，并且仅在存在可编辑筛选时显示；而 Backspace 会保留只读筛选（FR23）。它是一项 `[fix]`（DEC-4）：按契约只读筛选不可移除，因此 Clear all 中的“all filters”指每一个可移除的筛选，而移除只读筛选的 Clear all 属于缺陷。`onChange` 将 `index` 记载为受影响的位置，而第一个被移除的索引正是如此。它作为 `[fix]` 补丁版本发布。
- DEC-3 在 `popover` 呈现方式下不作任何改动。其 Clear all 遵循 FR23（DEC-4），抽屉呈现方式的 Clear all 与之相符；其日期遵循 FR25 和 FR26（DEC-5、DEC-6），抽屉呈现方式的日期与之相符。
- 一项稳定修复（DEC-5）：仅日期的 `date_absolute` 值在标记上、在无障碍标签与播报中、以及在编辑器中，在两种呈现方式下都读作一天（FR25）。调用方观察到的行为是：设置 `timezoneID` 时，标记、标签、导出的 `PowerSearchToken` 和编辑器都显示 `timezoneID` 中的那一天，而在编辑器中选中的一天会存储为该时区的午夜；未设置 `timezoneID` 时，存储的那一天保持为 UTC 午夜，标记、标签和 `PowerSearchToken` 显示 UTC 的那一天，不带任何时刻。运算符设置 `isDateOnly: false` 的值不受影响。以 `[fix]` 发布（`spec:AST-017` FR5、FR32）：已发布的浮层在三个时区中读取同一个仅日期值（标记在查看者时区，标签在 `timezoneID` 且带时刻，编辑器在 UTC 那一天），因此没有任何使用方能够合理地依赖某一天如何被存储或读取，而 `timezoneID` 是为日期格式化而记载的，所以遵循它即恢复该契约。
- 一项稳定修复（DEC-6）：`isDateOnly: false` 的 `date_absolute` 运算符在两种呈现方式下都是一个带时刻的瞬时值，而在浮层呈现方式下，它在时间字段旁的日期选择器中编辑，其标记显示时间（FR26）。调用方观察到的行为，仅针对设置 `isDateOnly: false` 的运算符：浮层的编辑器新增一个时间字段；从中保存的值携带所输入的时间，采用 `timezoneID`，否则采用查看者的时区，而在之前它携带的是所选日期的 UTC 午夜；标记在该时区中显示日期和时间，而在之前它仅显示设备上的那一天。`isDateOnly` 未设置或为 `true` 的 `date_absolute` 保持不变。以 `[fix]` 发布（`spec:AST-017` FR5、FR32）：`isDateOnly` 的记载是仅在为 true 时选择不带时间的日期选择器，而已发布的编辑器对每个值都使用该日期选择器并存储午夜，因此该选项不改变任何东西，也没有使用方能够合理地依赖它；遵循它即恢复该契约。
- 被拒绝的关闭（FR15c、`component:BottomSheet` DEC-5）：当丢弃确认打开时，Filters 抽屉（或入口的 Add filter 抽屉）停留在其窥视位置，而不是弹回到对话框下方的定位档位。对话框、其文字、焦点与结果、草稿、Done 以及 `onChange` 均不变，也没有 prop 变化。它是一项 `[feat]` 补丁变更（`spec:AST-017/FR7`、`/FR25`）。

使用方迁移说明属于使用方文档与发布说明。

## Ownership boundary

**拥有**

- 筛选器编辑器浮层的可读宽度范围。
- 识别打开编辑器的稳定控件：添加路径为内部的 typeahead 输入，编辑路径为实际被激活的标记/控件。
- 根据该打开控件的几何信息，选择受宽度上限约束的编辑器对齐到 PowerSearch 的哪一条外边缘。
- 在编辑器的宽度与水平对齐发生变化时，保持编辑流程、内容与焦点行为不变。
- 触摸抽屉呈现方式：其触发器，Filters、Add filter 与值抽屉，其中哪些同时打开、关闭时显示哪一个，每一步之后哪个控件获得焦点，值在步骤确认前的暂存，每次提交的 `onChange` 元数据，Clear all 的确认，以及抽屉遵循哪些 PowerSearch prop。

**不拥有 / 非目标**

- 主字段/搜索菜单宽度——既有的 `menuWidth` 使用方接口是一个转发给 Tokenizer 主字段菜单的精确像素宽度，不是最大值，也不是编辑器宽度控制。
- 通用锚点定位、视口碰撞处理、顶层托管或关闭——归 `architecture:layer-runtime` 所有。
- 编辑器内部的运算符菜单与值菜单尺寸。
- 用于覆盖编辑器宽度或位置的公共 prop。
- 指针坐标定位、指针与键盘的分支、持续的指针跟踪，或常驻的几何观察器。
- `adaptive` 背后的紧凑触摸判定规则。PowerSearch 使用与选择控件相同的共享策略来解析 `adaptive`（`component:Selector/FR4`）；它不新增自己的查询。
- 抽屉的对话框、打开的模态抽屉堆叠中那唯一一层遮罩、手势、吸附行为、键盘适配、哪个抽屉位于顶层因而接收关闭、被覆盖的抽屉如何退让，以及被关闭的顶层抽屉如何露出其下方的抽屉——归 `component:BottomSheet`（其抽屉栈）与 `family:overlay-dismissal` 所有。
- `string_list` 或 `entity_list` 值在值步骤内打开的列表值抽屉——归 `component:Tokenizer`（其 DEC-3 抽屉呈现方式）所有。

## Public concepts

引入一个稳定的公共概念：`presentation` prop，取值为 `'popover' | 'bottom-sheet' | 'adaptive'`，默认值为 `adaptive`，其类型为导出的 `PowerSearchPresentation`，即选择控件与 Tokenizer 使用的值集合（DEC-3）。

包含端点的 400–720 CSS px 范围以及编辑器浮层的条件对齐，是 PowerSearch 内部的可读性策略，而不是调用点的选项。既有的 `menuWidth` 仍然只是针对 `popover` 呈现方式的主字段/搜索菜单的精确像素宽度。

在抽屉呈现方式下，描述 tokenizer 的 typeahead 浮层的 prop 没有可作用的对象：`menuWidth` 和 `tokenOverflowBehavior`。当字段解析为 `bottom-sheet` 时传入两者中的任意一个，会在开发环境下发出一次警告，并指出 `presentation="popover"`；两者都不会被静默丢弃。`ref` 在两种呈现方式下都到达根元素，即本记录承诺的元素（`architecture:public-component-api/INV8`）；`xstyle`、`className` 和 `style` 在两种方式下都到达字段容器。`data-*` 属性（包括 `data-testid`）到达字段的主控件：在 `popover` 呈现方式下是组合框输入，在抽屉呈现方式下是触发器按钮。`components.Token` 和 `components.Editor` 的默认值 `PowerSearchToken` 与 `PowerSearchFilterEditor` 将 `data-*` 属性传递给标记以及编辑器的根元素。`handleRef.focusTypeahead()` 和 `blurTypeahead()` 作用于触发器。其他所有 prop 保持其含义：`label` 为触发器命名，`placeholder` 是它的空文本以及内容搜索的占位文本；`isDisabled`、`disabledMessage`、`startIcon`、`endContent`、`resultCount`、`status`、`statusVariant`、`size`、`hasAutoFocus`、`onFocus` 和 `onBlur` 如 FR11 所述作用于触发器；`hasClear` 管控 Clear all（FR12）；`isReadOnly` 管控各行、Add filter 和值步骤（FR12、FR13、FR15）；`maxSearchResults` 和 `maxOperatorMenuItems` 作用于 Add filter 与值步骤（FR13、FR17）；`popoverSaveButtonLabel` 和 `components` 作用于值步骤与触发器（FR11、FR14）；`maxTokenLength` 作用于触发器的标记，如同作用于浮层的标记（FR11）。`timezoneID` 指定抽屉呈现方式在触发器的标记、Filters 各行与日期编辑器中读写日期值所用的时区：仅日期值在那里是其那一天，否则为 UTC 的那一天；而运算符设置 `isDateOnly: false` 的值在那里是其日期与时间，否则在查看者的时区（FR11、FR12、FR17）。

### Allowed variation

- **AV1 — 视口钳制。** 当首选宽度或边缘对齐会越过其视口安全区域时，层运行时可以平移或收缩编辑器。
- **AV2 — 书写方向。** 只要渲染出的边缘在 LTR 与 RTL 中都正确，实现可以通过逻辑对齐值来表达所选定的物理边缘。
- **AV3 — 子菜单。** 运算符菜单与值菜单可以保留各自的宽度与碰撞行为；本契约仅适用于筛选编辑器 popover。
- **AV4 — 内部表示。** 共享的打开控件描述符可以使用 ref、元素或等价的包内部值。其可观察的几何、生命周期与优先级必须满足 FR3–FR9。
- **AV5 — sheet 流程组合。** sheet 呈现把它的各个步骤作为独立的 BottomSheet 承载，由单一的步骤状态驱动，每个步骤在其自身打开或位于某个打开的步骤之下时 `isOpen` 为 true（FR15a），因此堆叠是 `component:BottomSheet` 自己的（FR5–FR9），并且只有在 FR15a 指明的情形下，Filters 才在其他 sheet 关闭时打开；它可以用任意内部结构组合 List、RadioList、TextInput、Calendar、Button、Heading、EmptyState 与 Text，也可以按需加载整个界面，只要 FR10–FR21、AR4–AR6 与 PR5 成立，且该组合保持在 `architecture:component-style-authoring/INV7` 之内：每个打开的层只挂载一个呈现，任何内容都不挂载两次；并且，在流程的某个 sheet 打开时，粗指针下的打开流程位于细指针下弹出式呈现的打开编辑器之内；在顶层之下打开的每个 sheet 都是 DEC-3 连同其计数记录的所有者例外，超出打开层限额（`spec:AST-017/FR60`，`DEC-29`）。Tokenizer 的列表值 sheet 作为同一堆叠中又一个 sheet 在该步骤之上打开。
- **AV6 — sheet 布局。** sheet 的内边距、字段列表搜索阈值的视觉位置、行密度以及页脚按钮的宽度可以变化；每个 sheet 操作 44 px 的最小点击区域（AR5）以及主体内缩边上边到边的 Filters 行与字段行则是固定不变的。

### Transformation and precedence order

- **ORD1 — 宽度。** 解析外层 PowerSearch 宽度 → 应用 400 px 可读下限 → 应用 720 px 可读上限 → 向可用的视口宽度让步。
- **ORD2 — 打开控件。** 为当前这次打开解析出稳定的内层输入框或实际被激活的 token/控件。
- **ORD3 — 水平对齐。** 若上限未使编辑器变窄，则使用外层逻辑起始。否则比较打开控件在外层 PowerSearch 内部到两侧物理边缘的间距 → 选择更近的外层边缘 → 并列时使用外层逻辑起始。
- **ORD4 — 碰撞。** 在首选宽度与边缘选定之后，交由层运行时应用视口碰撞处理。

### Performance and resources

- **PR1 — 一次批量的打开时读取。** 响应打开意图时，PowerSearch MUST 一次性同时读取外层 PowerSearch 与打开控件的几何，绝不在 React 渲染期间读取。
- **PR2 — 先隐藏提交，后显示。** 放置状态 MUST 在编辑器 popover 隐藏期间提交，popover MUST 在下一个动画帧显示。真实 Chromium 验证 MUST 证明在默认或过时位置上没有首帧闪烁。
- **PR3 — 锁定，而非跟踪。** 已解析的打开控件与首选边缘 MUST 保持锁定直到关闭。实现 MUST NOT 安装持续的指针跟踪或常开的几何观察器。
- **PR4 — 响应式几何归 CSS 所有。** CSS 锚点尺寸计算与层运行时 MUST 掌管 400–720 的宽度策略与碰撞行为。JavaScript 可以选择每次打开时的锚点/对齐描述符，但 MUST NOT 持续计算弹窗宽度或碰撞偏移。
- **PR5 — sheet 表面是按需成本。** 处于 `popover` 呈现中的字段不加载 sheet 流程的代码；当字段解析为 `bottom-sheet` 时，该流程的 chunk 按需加载，因此第一次按下不会等待网络，也不会在服务端或水合渲染期间渲染任何内容。静止时该字段不渲染流程的任何部分：它的三个对话框、行、搜索字段、编辑器以及 Clear all 确认，只在从按下开始直到退场完成且焦点回到触发器为止的这段时间内挂载（`architecture:component-style-authoring/INV7`）；触发器、其末端通道（结果计数、`endContent`）以及 FR11 的字段外框则随字段一起渲染。

## Accessibility contract

- **AR1 — 各激活方式等价。** 对同一控件的指针、键盘与程序化激活 MUST 解析出相同的首选边缘。键盘用户保留当前的字段选择、编辑器焦点、遍历、应用/取消、Escape 以及焦点返回行为。
- **AR2 — 语义稳定性。** 宽度与放置 MUST NOT 改变当前的 combobox、listbox、option、menu 或编辑器的语义与可访问名称。
- **AR3 — 可见内容。** 视口钳制 MUST 使所有编辑器控件在水平方向上可达，而无需页面级横向滚动。
- **AR4 — 触发器语义。** 在 sheet 呈现中，触发器是一个由字段标签加上其可见文本命名的按钮，带有 `aria-haspopup="dialog"` 与 `aria-expanded`；`status.message` 与 `disabledMessage` 描述它；禁用的触发器使用 `aria-disabled` 并保留其焦点顺序；可交互的 `endContent` 是触发器的兄弟节点，有自己的名称与 Tab 停靠点，绝不是它的后代。
- **AR5 — sheet 语义。** 每个步骤都是一个由其标题命名的模态对话框（“Filters”、“Add filter”、值步骤的标题），打开的那个位于打开它的各 sheet 之上，后者在其下为 `inert`（`component:BottomSheet` FR6）；Filters 行、字段行与建议行都是由其可见文本命名的按钮，Filters 行的尾部删除操作是一个名为“Remove {field label} filter”的按钮，并以该名称作为其 tooltip；Clear all 确认是一个名为“Clear all filters?”的模态 `alertdialog`，其操作读作“Clear filters”与“Keep filters”，打开时焦点落在 Keep filters 上，因此误按 Enter 会保留筛选器；一个值选项是 `component:RadioList` 中的单选按钮（单选），或 `component:CheckboxList`（`enum_list`）中的复选框，由字段标签命名（FR17）；运算符步骤是一个名为“Operator”的 `component:RadioList`；内容搜索是一个名为“Search”的 searchbox，控制建议列表；字段列表搜索是一个名为“Search filters”的 textbox；除选择列表外，每个 sheet 操作都有至少 44 px 高的点击区域，而尾部删除操作与标题栏的 Add filter 保持其中等可见尺寸，其点击区域满足该下限。选择列表 —— 运算符与值的 RadioList 与 CheckboxList —— 则遵循标准列表密度及其共享触控带，如同它们在别处一样（所有者决定，cixzhang，2026-11-07）。
- **AR6 — 播报与焦点。** sheet 打开期间，流程发出的每一处播报 —— 对已提交的建议或值为 `empty` 的字段行的 `Added {label}`，对因其行的尾部删除操作而移除、因点按值为 `empty` 的筛选器的行而移除，或因调用方的 `Editor` 覆盖实现在编辑过程中调用 `onSave(null)`（FR14）而移除的筛选器的 `Removed {label}`（该标签是 Filters 行的文本 —— 即该行渲染的同一条“{label} {value}”目录消息，其摘要与相对日期值按 FR12 所述从目录解析；弹出式呈现中的移除是 Tokenizer 的 `tokenRemoved`，用的是该筛选器的 `formatFilterValue` 标签“{field}: {operator} {value}”—— 而不是 token 的文本：`1500` 配 `units: 'ms'` 在 token 上显示“1500”，播报为“1,500 ms”—— 而 sheet 中的移除是 Filters 行的文本，因此凡 FR12 的行与 `formatFilterValue` 不同的地方，两种读法就不同）、FR19 的结果计数、Add filter sheet 的空结果消息（“No results found”、“No filters match your search”，各为一个紧凑的 EmptyState（FR13）），以及值步骤的“This filter is no longer available”（FR14），即纯渲染文本，每一个都由共享的自有内容模块（`architecture:react-component-runtime/INV10`）从其渲染元素读取，并在每次无匹配的查询中播报一次，或在每个打开的筛选器上播报一次，且仅在该消息所属的 sheet 是当前打开的 sheet 时 —— 位于另一个 sheet 之下的 sheet，或关闭后保留其主体的 sheet，什么也不播报（FR18）—— 因此没有任何东西会把它们再播报一次，而重新打开同一个过时的筛选器会再次播报其消息 —— 这些播报由打开 sheet 内一个持久的 polite 实时区域投递：一个在其文本变化时保持挂载、且绝不会在已持有待播报文本的情况下挂载的元素（`spec:AST-086/FR3`），它以自身的 polite 紧急程度投递在其内部添加的内容（`spec:AST-086/FR4`），并且它就是打开的原生模态内部的所有者所采用的通道（`spec:AST-086/FR14`），因此播报能够到达原生模态对话框之后的辅助技术，而位于其外的通道则不能。Clear all 在仍有只读筛选器时播报“Editable filters removed”，否则播报“All filters removed”，位置在 Filters sheet 内，且在其确认对话框关闭之后 —— 不早于此，因为在此之前确认框是顶层模态并遮挡了该 sheet 的区域。结果计数跟随已应用的筛选器，而它们随 Done 变化（FR15b），因此流程内部的编辑不会改变任何计数；Done 之后、流程关闭期间，改变后的计数按 `spec:AST-086/FR14` 为字段当时位置所指明的通道投递（FR19）。焦点按 FR16 所述移动，并在流程关闭后返回触发器。

## Family and system relationships

- `architecture:layer-runtime` 负责锚点接线、碰撞回退、视口安全、顶层托管以及可见性校准。PowerSearch 提供其每次打开的首选宽度来源、稳定的打开控件以及边缘选择。
- `architecture:interaction-modality` 继续负责共享的模态状态，但编辑器的放置结果有意不按模态分支。
- `architecture:public-component-api` 负责公共表面标准。宽度与放置保持为内部，因为它们是组件可用性不变式，而不是采用方策略。`architecture:public-component-api/INV16` 管辖 DEC-3 新增的触摸呈现：精细指针表面——分词器字段及其编辑器浮层 `popover`——通过 presentation 值在每台设备上都保持可达；每种触摸模式都可被调用方使用，即在每台设备上为 `bottom-sheet`，在紧凑粗指针屏幕上为 `adaptive`；并且调用方显式指定的值优先于任何默认值。DEC-3 的默认值是 `adaptive`：INV16 使触摸成为“在服务触摸用户之处”的默认值，而在紧凑粗指针屏幕上，正是 sheet 流程这一表面在为这些用户服务。
- `family:overlay-dismissal` 继续负责共享的 Escape 与平台关闭顺序；DEC-1 与 DEC-2 不改变任何关闭行为，而 DEC-3 的 sheet 通过 `component:BottomSheet` 采用该 family 的关闭路径，正如这些 sheet 在对话框、遮罩、手势、吸附行为、键盘适配与关闭路径上声明的“不拥有”条目所述。
- `component:Tokenizer/DEC-1` 是包内部稳定的外层字段/打开控件描述符及其安全回退语义的当前权威。PowerSearch 只有在解析出比外层字段更窄的编辑器之后才使用该身份标识；Tokenizer 不贡献任何 PowerSearch 宽度策略。
- `component:Tokenizer/DEC-3` 负责 `string_list` 或 `entity_list` 值在值步骤内打开的 sheet 呈现；PowerSearch 将字段标签作为该 sheet 的标题传入，并且不对其行、搜索或 Clear all 作任何主张。
- `component:BottomSheet` 负责这些 sheet 的对话框、栈中的唯一遮罩、手势、键盘适配、被覆盖的步骤如何后退，以及被关闭的步骤如何显露其下方的那一步（FR15a）；该栈的顶层 sheet——值步骤、Add filter，或位于值步骤之上的 Tokenizer 列表值 sheet——是 Escape、遮罩点击、滑动以及平台关闭请求所到达的那一个（`component:BottomSheet` FR7），其中 Escape 与平台关闭的顺序由 `family:overlay-dismissal` 负责。
- `architecture:public-component-api/INV8` 管辖 `ref` 落在何处（本记录所承诺的根元素，在两种呈现中皆然）；`data-*` 属性，包括 `data-testid`，到达每种呈现的主要控件。PowerSearch 是一个组合，它使用 `family:input-fields` 的成员，但自身并不是该 family 的成员。
- `spec:AST-086/FR3`、`FR4` 与 `FR14` 管辖该流程自身的礼貌 live region：一个位于已打开 sheet 内部的持久容器，它投递添加到其中的内容，这也是所有者在已打开的原生模态框内部渲染的路由所走的路径，因为共享的页面主体通道在那里未被暴露。
- `spec:AST-017/FR3` 管辖该默认值变更。

### `spec:AST-013` FR12 exception — calendars that need `Temporal`

- **能力：** PowerSearch（两种呈现中的分词，以及 sheet 的 Filters 行与移除播报）与 PowerSearchToken 写入提供方日历（`spec:AST-111` FR18）的日期值，适用于公历、佛历、民国历与日本历之外的日历，它们需要运行时的 `Temporal`。
- **缩减：** 在 `Temporal` 缺失或不支持该日历的地方（例如 macOS 与 iOS 上的 Safari），此类日历在首次渲染前解析为 `gregory`，并在开发环境中于服务端与浏览器各警告一次，指出 `temporal-polyfill/full/global`（`spec:AST-111` FR5）。此后日期值显示公历日期；过滤值保持 Unix 秒。加载了 `Temporal` polyfill 的应用会得到完整日历。没有 `Temporal` 的服务端渲染公历文本，而带 `Temporal` 的浏览器与之不匹配，因此服务端渲染的应用也要在服务端加载 `Temporal`。
- **保留的义务：** `spec:AST-013` FR7 与 FR8，以及在中国历与檀纪历情形之外（`spec:AST-111` FR19）、服务端与浏览器以相同方式解析日历时始终成立的 FR9。过滤流程与过滤值不变；不会抛出任何异常。
- **证据：** 分别带有 `Temporal` polyfill 与移除 `Temporal` 的 `PowerSearch.calendarSystems.test.tsx`；`PowerSearchBottomSheet.test.tsx`（“在提供方日历中写入触发分词与 Filters 行”）。证据缺口：在需要 `Temporal` 的日历下，没有真实浏览器运行，也没有服务端渲染与注水测试。
- **所有者：** `nynexman4464`。
- **审查条件：** Safari 发布 `Temporal`。

## Decision log

### DEC-1 — PowerSearch owns one internal readable editor width

**Reference:** `component:PowerSearch/DEC-1`

**Decider:** `cixzhang`, 2026-08-31

一个过宽的编辑器会让“字段/算子/值”这类小任务更难扫读，而由调用点提供宽度 prop 则会把可读性策略变成永久的公共 API，并产出一致性不佳的产品。因此 PowerSearch 自己拥有一个内部首选范围：外层 PowerSearch 宽度先夹取到 400–720 CSS px，再受视口约束。该规则不改变 Tokenizer 主菜单的尺寸，也不改变 PowerSearch 现有的精确像素 `menuWidth` 表面。

已否决：公开的编辑器 width/max-width prop、把 720 上限套用到 Tokenizer 的主菜单，或把 `menuWidth` 当作编辑器宽度。

### DEC-2 — Only a capped editor follows the stable opening control

**Reference:** `component:PowerSearch/DEC-2`

**Decider:** `cixzhang`, 2026-08-31

全宽或按下限扩张的编辑器仍对齐到外层 PowerSearch。只有当 720 px 上限使编辑器变窄时，PowerSearch 才使用稳定的打开控件来选择更近的外边缘。添加路径使用内层的 typeahead 输入框；编辑路径使用实际被激活的 token/控件。该控件的几何形状对指针、键盘和编程式激活给出相同结果，且结果在关闭前保持不变。

已否决：按指针坐标放置、区分指针与键盘分支、始终使用同一条边缘、把每种宽度都锚定到内层控件、持续跟踪、在渲染时读取几何信息，以及在隐藏的放置状态提交之前就显示。

### DEC-3 — The touch sheet is a stable presentation, and adaptive is the default

**Reference:** `component:PowerSearch/DEC-3`

**Decider:** `imdreamrunner`, 2026-11-03

PowerSearch 通过一个稳定的 `presentation` prop 提供其触摸表面，取值包括选择控件和 Tokenizer 所使用的 `popover`、`bottom-sheet` 和 `adaptive`，且 `adaptive` 是默认值：在紧凑的粗指针屏幕上使用 sheet 流程（此时编辑器 popover 会与软键盘争夺空间），在其他所有地方则使用 tokenizer 字段及其编辑器 popover。调用方显式指定的值在任何设备上都优先，而 `popover` 保留 tokenizer 字段与编辑器 popover（`architecture:public-component-api` INV16）。`adaptive` 通过共享的紧凑粗指针策略解析，因此同一页面上的 PowerSearch、Tokenizer 和 Selector 会一起切换。这个稳定的 prop 与 `adaptive` 默认值在同一个补丁版本中一起发布：API 变更是增量的，行为只在紧凑粗指针屏幕上改变，而 `presentation="popover"` 在其他所有地方都保持原有行为。该发布层级是工程负责人的产品决定，并得到 `spec:AST-017` 所有者之一 `cixzhang` 的同意。已否决：继续把 `popover` 作为默认值，因为这样一来，除非调用方主动选择加入，否则手机会在软键盘下方得到编辑器 popover（`component:Selector` DEC-1 出于同样理由否决了同一默认值）。

sheet 表面：整个字段是一个触发器，其 token 仅用于显示；Filters sheet 把各个筛选条件列为行，行尾带移除操作，位于带 Add filter 的固定页眉之下、带 Done 和 Clear all 的固定页脚之上，为空时则是一个居中的 Add filter；Add filter 打开在 Filters 之上并列出各字段，或承载带内联建议的内容搜索，其搜索在被点击之前不聚焦；值步骤打开在引导出它的那个 sheet 之上，按算子 → 值暂存，编辑器位于该 sheet 的表面上，并从其页脚确认。每一步都保留在下一步之下，因此关闭一步会显露上一步，任何 sheet 都不需要 Back 操作。封闭词表是行；列表值通过 Tokenizer 的 sheet 呈现来编辑，标题使用字段标签；`nested` 值使用 popover 呈现内置的嵌套编辑器；仅日期值在 `timezoneID`（否则 UTC）中的内联 Calendar 上编辑，带时刻的值在 `timezoneID`（否则查看者的时区）中的日期时间控件上编辑；其他每种值类型都使用 popover 呈现所用的编辑器。Clear all 会请求确认，移除该人可以编辑的筛选条件，保留只读的，并让 Filters 保持打开。该流程编辑一份草稿，Done 时应用它；草稿有改动时的关闭会在丢弃前询问（FR15b、FR15c、DEC-7）。该流程固定的七个细节：没有 `timezoneID` 的仅日期值是它的 UTC 日期；每个算子都是 `nested` 的字段以列表呈现，并通过内置嵌套编辑器编辑；每个字符串都来自 catalog（FR20）；Add filter 的各次搜索的空结果沿用 Core 的标题（FR13）；在没有只读筛选条件残留时，Clear all 显示 “All filters removed”（AR6）；从字段行一键添加的 `empty` 筛选条件会宣告为 `Added {label}`（AR6）；以及在按下之前该流程不挂载任何内容（PR5）。已否决：用 Back 操作原地互相替换的步骤（该流程的一个早期草案）：那样关闭会在任何步骤关闭整个流程，而人要重新从其入口点进入 Filters，而不是在离开处找到它。已否决：值步骤页脚中的 Remove（第二条移除路径，只有打开该步骤才能到达；行尾操作一次点击即可移除）。已否决：打开时聚焦 Add filter 的搜索（软键盘随后会盖住人来看的那些行）。已否决：由调用方选择的独立触摸组件（两个组件、两份草稿状态、每个断点一次导入替换）。

对 `architecture:component-style-authoring/INV7` 的层预算的所有者例外：该流程让每一步都保留在下一步之下（FR15a），因此在值步骤打开时，会同时挂载两到三个 sheet——每一个都是这个栈中被覆盖的 sheet（`component:BottomSheet` FR6：后退、被阻塞、状态保留，以便人在离开处找到它）——而在 Tokenizer 的列表值 sheet 打开在某个创建过程的值步骤之上时，是四个；Clear all 确认打开在 Filters 之上时以同样方式覆盖它；每个被覆盖的 sheet 都是一个完整对话框，超出了 5 个元素的打开层配额（`spec:AST-017/FR60`、`DEC-29`）。现有元素做不到这件事：被替换的步骤必须在返回时重建，其暂存状态和滚动位置也要重新创建，而关闭无法显露它。这些计数是在 390×844 下 `document.body.querySelectorAll('*').length` 的取值。AV5 用来衡量该流程的边界是精细指针下 Adaptive（默认）故事中 popover 呈现的打开编辑器：334，静止时为 166。该 story 在粗指针下的 sheet 流程，每个状态都在稳定后读取一次（每个打开的对话框都属于该状态自身，相隔一秒的两次读数一致），读数为静止时 123、Filters 打开时 313、Add filter 在 Filters 之上时 314、选择行值步骤在两者之上时 332、列表值步骤在两者之上时 349、而 Tokenizer 的列表值 sheet 在该步骤之上时 420、编辑步骤在 Filters 之上时 373、Clear all 确认在 Filters 之上时 333。从第一次按下直到退出完成，它保持已关闭的 Add filter sheet 和值步骤处于挂载状态，这构成了从 123 到 313 的大部分增量；确认只在它打开期间挂载。

对 INV7 表面预算的所有者例外，该预算要求指针专属的呈现是对同一批元素的属性和样式的改变：在 `adaptive` 下，已关闭的字段按指针交换其元素——以 tokenizer 字段及其组合框输入和 token 移除控件，换成一个持有仅展示 token 的触发器按钮（FR11）——因为两个表面的角色不同（一个是内联编辑的组合框，一个是打开模态流程的按钮），而组合框无法在不歪曲其角色的情况下重设为对话框触发器。该交换渲染的元素更少，而非更多（静止时 123 对 166），并且只发生在分辨率变化时（FR10）；Tokenizer 自己的 `adaptive` 触发器记录了同样的例外。

sheet 呈现的 Clear all 保留只读筛选条件（它们属于使用方），并在草稿中第一个被移除的索引处记录一个 `remove`，由 Done 上报，而 popover 呈现的 Clear all 会立即上报它（FR23、DEC-4、FR15b）。它的日期编辑器、token 和行，把仅日期的 `date_absolute` 值以及 `date_range` 的每个绝对部分，读写成同一时区中的一天：prop 设置时为 `timezoneID` 中的日期，否则为 UTC 日期；算子设置 `isDateOnly: false` 的值是带时刻的瞬时值，在 `timezoneID` 中读写，否则在查看者的时区中读写（FR11、FR12、FR17）。`popover` 呈现以同样方式读取这两者（FR25、FR26；DEC-5、DEC-6）。

### DEC-4 — Clear all keeps read-only filters

**Reference:** `component:PowerSearch/DEC-4`

**Decider:** `imdreamrunner`, 2026-11-02

只读筛选条件按契约不可移除：它没有移除控件，也没有任何按键或批量操作能移除它。因此 Clear all 中的“所有筛选条件”指每一个可移除的筛选条件，而移除只读筛选条件的 Clear all 是缺陷。Clear all 移除可编辑的筛选条件，保留只读的，并在第一个被移除的索引处上报 `remove`——在 popover 呈现中立即上报，在 sheet 呈现中于 Done 时上报（FR15b）。当最后一个筛选条件是只读时，空输入框上的 Backspace 不会移除任何内容（FR23）。已否决：同时移除只读筛选条件的 Clear all（一个单独无法移除的筛选条件会随其余一并消失）。

### DEC-5 — A date-only value is one day in one zone

**Reference:** `component:PowerSearch/DEC-5`

**Decider:** `imdreamrunner`, 2026-11-02

算子未设置 `isDateOnly` 或将其设为 `true` 的 `date_absolute` 值，以及 `date_range` 的每个绝对部分，都是一个日历日。`timezoneID` 设置后，就是读取和写入该日期的唯一时区：token 的文本、无障碍标签、宣告、sheet 的各行，以及两种呈现的编辑器，都显示该瞬时值在该时区中所落的那一天，而在编辑器中选中的一天会存储为该时区的午夜。没有 `timezoneID` 时，该日期就是 UTC 日期，读写皆然，因此调用方按 UTC 午夜存储的值无论设备时区如何都保持其日期和瞬时值。已否决：让 token 保持设备时区（UTC 午夜的日期在 UTC 以西的任何地方都会被读成前一天，编辑器随后打开在与 token 显示不同的一天，于是重新选择 token 的日期每次都会把值提前一天）。已否决：把查看者的时区作为仅日期值的回退（存储的 UTC 午夜日期随后会被显示，并在编辑时在每个 UTC 以西的设备上重写为不同的瞬时值；UTC 回退不改变任何已存储的值）。已否决：为编辑器时区单独提供一个 prop（一个字段，一个时区；`timezoneID` 已经指明了它）。

### DEC-6 — `isDateOnly: false` is an instant with a time of day

**Reference:** `component:PowerSearch/DEC-6`

**Decider:** `imdreamrunner`, 2026-11-02

设置 `isDateOnly: false` 的 `date_absolute` 算子指代一个带时刻的值。它的 popover 编辑器是日期选择器旁边加一个时间字段（sheet 的控件是 FR17 的），其 token 显示日期和时间，两者都在 prop 设置时于 `timezoneID` 中读写该瞬时值，否则在查看者的时区中读写：瞬时值没有自己的日期需要稳定，人就在自己所处的地方读取它；需要每个查看者都看到同一个挂钟时间的字段会传入 `timezoneID`。`isDateOnly` 未设置或为 `true` 的算子保留日期选择器。已否决：为 `isDateOnly: false` 使用仅日期编辑器（该选项唯一有文档的含义就是带时刻的值，而仅日期编辑器存储午夜并且不显示时间，于是该选项什么也没改变）。已否决：把 UTC 作为瞬时值的回退时区（人输入的挂钟时间随后所指的是与他们时钟上读到的小时不同的小时）。已否决：为每个 `date_absolute` 值在 token 上显示时间（日历日没有时间可显示）。

### DEC-7 — The sheet edits a draft that Done applies, and asks before discarding a changed one

**Reference:** `component:PowerSearch/DEC-7`

**Decider:** `imdreamrunner`, 2026-11-04, with the designer's confirmation

sheet 呈现从打开起就持有一份筛选条件列表的草稿：添加、编辑和移除筛选条件以及 Clear all 都会改变该草稿，而字段的 `onChange` 只在 Done 应用它时被调用（FR15b）。草稿有改动时的关闭会通过 Tokenizer sheet 所使用的确认来在丢弃前询问（FR15c）。该保存模型就是 `component:Tokenizer` DEC-4 为其 sheet 所陈述的那一个，因此 PowerSearch 流程堆叠的两个 sheet——筛选条件列表和一个列表值的 Tokenizer——以相同方式提交：通过显式操作，绝不在手指之下提交。Done 通过公开的 `onChange(filters, changeType, index)` 上报草稿，做法是把记录的编辑按顺序重放到字段最新的 `filters` 上，每次调用都携带该次编辑之后的列表：使用方收到的调用与 popover 会话所做的调用相同，带有真实的 change type 和索引；只保留最后一次调用列表的使用方最终落在已应用的列表上，因为每次调用都携带整个列表；而父级在该流程打开期间添加的筛选条件——尤其是只读的那个——会保留下来，因为重放从包含它的列表开始。如果某次编辑或移除的目标同时已被父级移除，则跳过该项，且不为它上报任何内容。已否决：为整份草稿只调用一次（公开的 `changeType` 没有对应批次的值，而发明一个值就是 API 变更；按类型分支的使用方会收到它不认识的一个类型）。已否决：只重放净编辑（按每次变更记录或响应的使用方会看到一段从未发生过的编辑历史）。已否决：在每次关闭时应用草稿（那样一次滑动或一次点击遮罩就会误提交，而确认正是为了防止这一点）。已否决：在打开的流程内显示受控父级的 `filters` 变更（草稿是该流程自己的列表；该变更在 Done 时参与，并在下次打开时显示）。已否决：按记录重放草稿自己的各份列表（父级在流程打开期间添加的筛选条件会在 Done 时被替换掉）。

## Open questions

- 已知差距，在 popover 呈现中早已存在，针对 `architecture:internationalization/INV1a`：它的 token 把列表、日期范围和嵌套摘要（“{n} items”、“date range”、“{n} filters”）写成英文字面量，用字面的“, ”连接列表值的各项，而 FR12 的各行使用区域设置的列表格式，并且把相对日期值显示为存储的键（`3d_ago`），其相对日期编辑器把选项标签（“3 days ago”）写成英文字面量。`formatFilterValue` 从 catalog 解析其摘要，但在四处与 token 不同：对实体列表它说 “{n} entities”，而 token 说 “{n} items”；它按区域设置的数字格式格式化 `integer` 或 `float` 并附加算子的 `units`，而 token 打印原始数字；当拼接后的文本超出宽度预算时，它把列表折叠成一个计数，而 token 比较的是标签的总长度，因此两者在不同长度处折叠；并且它以不同长度和不同标记截断单个值——token 的预算是 `maxTokenLength` 减去字段和算子标签的长度，至少为 10，留 3 个字符的余量并用 “...”（三个句点），而 `formatFilterValue` 在 `maxTokenLength` 处以 “…”（省略号字符）截断——（两者都把相对日期值按其存储形式显示）。sheet 呈现在其自身的各个表面上从 catalog 或区域设置的格式解析所有这些（FR12、FR20），并在触发器上显示 popover token 的文本，日期除外，FR11 在 `timezoneID` 或其回退时区中读取它；改变 token 和编辑器自身的文本是所有者的一项独立的稳定变更。
- 针对 `family:input-fields/FR10` 的已知差距，由 DEC-3 开启：sheet 呈现的触发器为 tokenizer 字段所具有的盒子组合了 Field，因此 PowerSearch 是一个组合 Field 的组件，而 FR10 即使在该 family 的成员资格之外也约束它，且本记录在两处偏离 FR10。第 1 项：`ref`、`id`、`data-*`、`aria-*`、`hidden`、`inert`、`dir` 和 DOM 事件处理器在 FR10 下都去往主语义控件，而本记录在两种呈现中都把 `ref` 保留在根上（即上文的 INV8 承诺），把 `data-*` 属性（含 `data-testid`）如 FR10 那样路由到主控件，并且完全不转发 `id`、`aria-*`、`hidden`、`inert`、`dir` 或处理器。第 2–4 项：PowerSearch 的稳定 props 携带根的 `xstyle`、`className` 和 `style`，两种呈现都把它们应用到字段盒上——即 FR10 的 `container*` 目标——因此样式落在 FR10 所放的位置，但 props 类型仍接受根名称，且不提供 `container*` 或 `control*` 部件。移动 `ref` 或移除根名称对现有调用方是稳定的 API 变更（`spec:AST-017/FR5`），因此这次转换是一项独立的稳定决策，带有自己的迁移，而不是 DEC-3 的一部分；DEC-3 的实现把 PowerSearch 加入 family 覆盖检查的待处理列表，它会一直留在那里，直到该决策或 family 记录的一项修订解决了哪条规则管辖一个消费成员行为的组合。
